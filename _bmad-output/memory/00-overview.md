# AI-Automated-office 记忆架构总览

## 一、架构定位与目标

### 1.1 核心定位

记忆架构是 AI-Automated-office Agent 系统的**认知核心**，负责存储、检索和重建 Agent 的认知状态。它不是简单的数据存储，而是**认知假肢（Cognitive Prosthetic）**——扩展 Agent 的认知能力。

### 1.2 设计目标

| 目标 | 说明 | 衡量标准 |
|------|------|----------|
| **认知连续性** | 跨会话保持上下文和知识 | 会话恢复时间 < 3秒 |
| **高效检索** | 快速定位相关信息 | 检索延迟 < 200ms |
| **令牌经济** | 优化上下文窗口使用 | 压缩率 > 60% |
| **认知重建** | 恢复完整的认知状态 | 状态重建准确率 > 90% |
| **多租户隔离** | 租户数据完全隔离 | 零数据泄露 |

### 1.3 与现有架构的融合

记忆架构位于 Agent 四层架构的**记忆层**，与感知层、决策层、执行层紧密协作：

## 二、核心设计理念

### 2.1 三层记忆架构（PRD需求）

基于 PRD 文档 FR501-FR525 的三层记忆设计：

```
┌─────────────────────────────────────────────────────────────────┐
│                    三层记忆架构                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  L1: 会话记忆 (Session Memory)                                  │
│  ├── 生命周期：会话期间                                         │
│  ├── 存储：当前会话的对话历史、工具调用记录                     │
│  ├── 容量：最近 N 轮对话（可配置，默认 50 轮）                  │
│  ├── 检索：时间序列访问                                         │
│  └── 清理：会话结束或压缩后归档                                 │
│                                                                 │
│  L2: 个人记忆 (Personal Memory)                                 │
│  ├── 生命周期：长期持久化                                       │
│  ├── 存储：用户偏好、常用操作、关键事实、决策历史               │
│  ├── 容量：无限制（向量检索）                                   │
│  ├── 检索：语义相似度 + 时间衰减                                │
│  └── 更新：关键事实自动提取                                     │
│                                                                 │
│  L3: 知识库记忆 (Knowledge Memory)                              │
│  ├── 生命周期：长期持久化                                       │
│  ├── 存储：企业知识、部门知识、项目知识                         │
│  ├── 容量：无限制（向量检索）                                   │
│  ├── 检索：RAG 混合搜索（向量 + BM25）                          │
│  └── 更新：知识库管理员维护                                     │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 四层存储架构（技术实现）

融合 claude-mem 和 brain-mcp-cli 的设计理念：

```
┌─────────────────────────────────────────────────────────────────┐
│                    四层存储架构                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  L4: 认知状态层 (Cognitive State)                               │
│  ├── 思考阶段（exploring/crystallizing/refining/executing）     │
│  ├── 开放问题追踪                                               │
│  ├── 决策历史                                                   │
│  ├── 情感基调                                                   │
│  └── 对应人脑的【情景记忆 + 元认知】                            │
│                                                                 │
│  L3: 结构化摘要层 (Structured Summary)                          │
│  ├── 对话摘要                                                   │
│  ├── 关键洞察                                                   │
│  ├── 概念提取                                                   │
│  ├── 领域分类                                                   │
│  └── 对应人脑的【语义记忆】                                     │
│                                                                 │
│  L2: 语义向量层 (Semantic Vector)                               │
│  ├── 消息嵌入向量                                               │
│  ├── 摘要嵌入向量                                               │
│  ├── 语义相似度索引                                             │
│  └── 对应人脑的【联想记忆机制】                                 │
│                                                                 │
│  L1: 原始数据层 (Raw Data)                                      │
│  ├── 对话消息（SQLite）                                         │
│  ├── 元数据（时间、来源、部门）                                 │
│  ├── 特征标记（代码、URL、问题）                                │
│  └── 对应人脑的【感觉记忆】                                     │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.3 核心设计原则

| 原则 | 说明 | 实现方式 |
|------|------|----------|
| **渐进式披露** | 分层检索，按需加载详情 | 索引层 → 时间线层 → 详情层 |
| **认知状态重建** | 保存"当时在想什么"，而非仅"发生了什么" | tunnel_state 工具 |
| **令牌经济学** | 优化上下文窗口使用，降低成本 | 压缩策略 + 关键事实提取 |
| **边缘处理** | 敏感数据在摄入层剥离 | Hook 层隐私标签处理 |
| **多租户隔离** | 租户数据完全隔离 | 数据库级隔离 + 租户前缀 |

## 四、与现有系统的集成点

### 4.1 与 Agent 核心的集成

| 集成点 | 位置 | 功能 |
|--------|------|------|
| **系统提示词构建** | `src/agents/system-prompt.ts` | 注入记忆上下文 |
| **上下文管理** | `src/agents/context.ts` | 获取压缩上下文 |
| **会话管理** | `src/routing/` | 会话Key格式兼容 |
| **工具系统** | `src/agents/tools/` | 记忆检索工具 |

### 4.2 与插件系统的集成

| 集成点 | 说明 |
|--------|------|
| **部门记忆隔离** | 每个部门插件有独立的记忆空间 |
| **会话Key格式** | `{tenantId}:{pluginId}:{sessionId}` |
| **权限控制** | 记忆访问受部门权限模型约束 |
| **知识库共享** | L3 知识库记忆可跨部门共享 |

### 4.3 与多租户架构的集成

| 集成点 | 说明 |
|--------|------|
| **数据库隔离** | 每个租户独立的 SQLite 数据库 |
| **向量索引隔离** | 每个租户独立的 LanceDB 实例 |
| **会话Key前缀** | 租户ID作为会话Key第一段 |
| **数据同步** | 租户数据独立同步到云端 |

## 六、技术选型

### 6.1 存储技术

| 层级 | 技术 | 理由 |
|------|------|------|
| L1 原始数据 | SQLite + FTS5 | 轻量、嵌入式、全文搜索、成熟稳定 |
| L2 语义向量 | LanceDB | 无服务器、支持混合检索、与Pandas无缝集成 |
| L3 结构化摘要 | SQLite | 与L1共享连接，事务一致性 |
| L4 认知状态 | SQLite + 内存缓存 | 快速访问，持久化备份 |

### 6.2 嵌入模型

| 场景 | 推荐模型 | 维度 | 说明 |
|------|----------|------|------|
| 默认 | FastEmbed (BAAI/bge-small-en-v1.5) | 384 | 轻量(107MB)、快速、质量足够 |
| 高质量 | text-embedding-3-small | 1536 | OpenAI 嵌入，高质量 |
| 中文优化 | bge-large-zh-v1.5 | 1024 | 中文语义理解更好 |

### 6.3 运行时环境

| 组件 | 技术 | 说明 |
|------|------|------|
| 桌面端 | Tauri + Rust | 与现有架构一致 |
| Agent运行时 | Node.js / Bun | 兼容 OpenClaw 架构 |
| 数据库 | bun:sqlite | 高性能 SQLite 绑定 |
