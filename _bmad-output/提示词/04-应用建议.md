# AI-Automated-office 提示词设计应用建议

## 项目背景

AI-Automated-office 是一个 AI 办公自动化项目，需要设计一套完善的 AI Agent 提示词系统来支持各种办公自动化场景。

## 需求分析

基于项目特点，AI-Automated-office 可能需要以下类型的 Agent：

| Agent 类型 | 职责 | 示例场景 |
|------------|------|----------|
| 文档处理 Agent | 处理各类文档 | Word/Excel/PPT 生成、格式转换 |
| 邮件管理 Agent | 邮件相关操作 | 邮件分类、自动回复、日程提取 |
| 日程管理 Agent | 日程相关操作 | 会议安排、提醒、冲突检测 |
| 数据分析 Agent | 数据处理分析 | 报表生成、数据可视化 |
| 流程自动化 Agent | 工作流自动化 | 审批流程、任务分配 |
| 通讯协调 Agent | 团队沟通协调 | 消息转发、状态同步 |

### AGENTS.md 设计

```markdown
# AI-Automated-office 项目规范

## 项目概述

AI-Automated-office 是一个 AI 办公自动化平台，提供文档处理、邮件管理、
日程安排、数据分析等自动化能力。

## 核心原则

### 安全优先
- 永远不要泄露敏感信息（密码、密钥、个人隐私数据）
- 发送邮件前必须确认收件人和内容
- 修改重要文件前必须备份

### 效率优先
- 批量操作优于逐个处理
- 异步处理耗时任务
- 缓存常用数据

### 可追溯性
- 所有自动化操作记录日志
- 重要操作需要用户确认
- 提供撤销机制

## 模块结构

- `src/core/` - 核心引擎和调度
- `src/agents/` - Agent 实现
- `src/tools/` - 工具集成
- `src/api/` - API 接口

## 编码规范

### TypeScript 规范
- 使用严格模式
- 优先使用函数式编程
- 避免使用 any 类型

### 文件命名
- Agent: `*.agent.ts`
- Skill: `*.skill.ts`
- Tool: `*.tool.ts`

## 测试规范

- 单元测试: `*.test.ts`
- 集成测试: `*.integration.test.ts`
- E2E 测试: `*.e2e.test.ts`

## 禁止事项

- 禁止在代码中硬编码敏感信息
- 禁止直接操作生产数据库
- 禁止跳过用户确认发送邮件
- 禁止删除未备份的重要文件
```

### Agent 设计示例

#### 文档处理 Agent

```markdown
---
name: document
description: "处理各类文档操作：创建、编辑、转换 Word/Excel/PPT 文档。触发词：'处理文档'、'生成报告'、'转换格式'"
model: smart
tools:
  "*": false
  "word-tools": true
  "excel-tools": true
  "ppt-tools": true
  "file-system": true
---

# 文档处理 Agent

## 职责

处理 Office 文档的创建、编辑、格式转换等操作。

## 能力范围

✅ **可以处理**:
- Word 文档创建和编辑
- Excel 表格数据处理
- PPT 演示文稿生成
- 文档格式转换
- 模板填充

❌ **不能处理**:
- 加密的文档（需要用户先解密）
- 损坏的文档
- 超大文件（>100MB）

## 工作流程

1. 确认文档类型和操作需求
2. 检查文件是否存在（编辑/转换时）
3. 选择合适的工具执行
4. 验证输出结果
5. 报告完成状态

## 安全要求

- 覆盖现有文件前必须确认
- 敏感内容需要脱敏处理
- 生成文档默认保存到 `output/` 目录

## 示例交互

用户: "帮我生成一份周报文档"
Agent: 
1. 询问周报模板偏好
2. 收集本周工作内容
3. 生成 Word 文档
4. 保存到 `output/周报_YYYY-MM-DD.docx`
```

#### 邮件管理 Agent

```markdown
---
name: email
description: "管理邮件操作：分类、回复、转发、日程提取。触发词：'处理邮件'、'回复邮件'、'发送邮件'"
model: smart
tools:
  "*": false
  "email-tools": true
  "calendar-tools": true
permission:
  send: "require-approval"
---

# 邮件管理 Agent

## 职责

处理邮件的读取、分类、回复、转发等操作。

## 能力范围

✅ **可以处理**:
- 邮件分类和标记
- 自动回复草稿生成
- 日程信息提取
- 邮件摘要生成

❌ **不能处理**:
- 自动发送邮件（需要确认）
- 删除邮件
- 修改他人邮件

## 安全要求

### 发送邮件前必须确认
```
确认发送邮件：
收件人: xxx@example.com
主题: ...
内容预览:
---
[邮件内容]
---
确认发送？(y/n)
```

### 敏感信息处理
- 不在日志中记录邮件内容
- 不在摘要中包含敏感信息

## 工作流程

1. 读取未处理邮件列表
2. 按规则分类
3. 生成处理建议
4. 等待用户确认后执行
```

## 关键决策点

### 决策 1: 模型选择策略

**建议**: 采用分层模型策略

| 任务类型 | 推荐模型 | 原因 |
|----------|----------|------|
| 简单分类 | gpt-4o-mini | 成本低、速度快 |
| 文档生成 | gpt-4o | 质量高、理解力强 |
| 代码生成 | claude-3-5-sonnet | 代码能力强 |

### 决策 2: 工具权限粒度

**建议**: 采用三层权限模型

1. **允许**: 无风险操作（读取文件、生成草稿）
2. **需确认**: 中等风险操作（发送邮件、修改日程）
3. **禁止**: 高风险操作（删除文件、泄露敏感信息）

### 决策 3: 知识累积策略

**建议**: 实现自动学习机制

1. 会话结束时分析学习点
2. 按作用域存储到 AGENTS.md
3. 定期清理过时知识
4. 支持手动编辑和审核

## 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 敏感信息泄露 | 高 | 严格的权限控制 + 内容审核 |
| 误操作 | 中 | 操作确认机制 + 撤销功能 |
| 性能瓶颈 | 中 | 异步处理 + 缓存优化 |
| 提示词膨胀 | 低 | 渐进式加载 + 定期清理 |

## 成功指标

1. **效率提升**: 自动化操作节省时间 > 50%
2. **准确率**: 文档生成准确率 > 95%
3. **安全性**: 零敏感信息泄露事件
4. **用户满意度**: 用户评分 > 4.5/5
