# AI Agent 系统提示词设计研究总览

## 研究目标

本研究旨在深入分析 `opencode` 和 `openclaw` 两个开源项目的系统提示词设计理念和原则，为 `AI-Automated-office` 项目的 AI Agent 提示词设计提供参考依据。

## 研究对象

### OpenCode 项目
- **定位**: AI 编程助手工具
- **技术栈**: TypeScript, Bun, SolidJS
- **提示词结构**: `.opencode/` 目录 + `AGENTS.md` 文件

### OpenClaw 项目
- **定位**: AI Agent 平台/框架
- **技术栈**: TypeScript, Node.js
- **提示词结构**: `AGENTS.md` + `.pi/prompts/` + `skills/*/SKILL.md`

## 核心发现

### 1. 分层架构设计

两个项目都采用了**分层提示词架构**，实现了关注点分离：

| 层级 | OpenCode | OpenClaw | 职责 |
|------|----------|----------|------|
| 项目级 | `AGENTS.md` (根目录) | `AGENTS.md` (根目录) | 项目规范、编码风格、工作流程 |
| 模块级 | `packages/*/AGENTS.md` | `src/*/AGENTS.md` | 模块特定知识、技术细节 |
| 任务级 | `.opencode/agent/*.md` | `.pi/prompts/*.md` | 特定任务指令 |
| 技能级 | `.opencode/command/*.md` | `skills/*/SKILL.md` | 可复用技能定义 |

### 2. 元数据驱动

两个项目都使用 **YAML Frontmatter** 作为提示词元数据声明：

```yaml
---
description: "任务描述"
model: opencode/claude-haiku-4-5
mode: primary | subagent
tools:
  "*": false
  "github-triage": true
---
```

这种设计允许：
- 声明式配置模型选择
- 工具权限控制
- 执行模式指定

### 3. 渐进式加载

**OpenClaw 的 Skill 系统**体现了渐进式加载原则：

```
元数据 (name + description) → 始终加载 (~100词)
SKILL.md 主体 → 触发时加载 (<5k词)
捆绑资源 → 按需加载 (无限制)
```

### 4. 知识累积机制

**OpenCode 的 `learn` 命令**展示了知识累积的设计思路：

- 从会话中提取非显而易见的学习内容
- 按作用域放置到相应层级的 `AGENTS.md`
- 保持条目简洁（1-3行）

## 设计原则总结

### 原则一：上下文效率优先
- 避免冗余解释，假设 AI 已具备基础知识
- 使用代码示例代替冗长描述
- 分层加载，按需提供上下文

### 原则二：声明式配置
- 使用 YAML Frontmatter 声明元数据
- 工具权限、模型选择、执行模式都可配置
- 配置与内容分离

### 原则三：模块化与可组合
- Agent/Command/Skill 作为独立模块
- 可组合
