# OpenCode 项目提示词设计分析

## 项目概述

OpenCode 是一个 AI 编程助手工具，其提示词系统设计精巧，体现了现代 AI Agent 提示词工程的最佳实践。

## 核心设计模式

### 1. Agent 设计模式

Agent 是具有特定职责的 AI 代理，处理特定类型的任务。

#### Agent 文件结构

```markdown
---
mode: primary | subagent
hidden: true | false
model: opencode/claude-haiku-4-5
color: "#44BA81"
tools:
  "*": false
  "github-triage": true
---

[Agent 指令内容]
```

#### Agent 类型

| 类型 | 说明 | 示例 |
|------|------|------|
| primary | 主 Agent，独立运行 | triage.md |
| subagent | 子 Agent，被其他 Agent 调用 | translator.md |

#### Agent 示例分析：triage.md

```yaml
---
mode: primary
hidden: true
model: opencode/minimax-m2.5
color: "#44BA81"
tools:
  "*": false
  "github-triage": true
---
```

**设计要点**：
1. **工具隔离**: `"*": false` 禁用所有工具，只启用特定工具
2. **模型选择**: 针对任务特点选择合适的模型
3. **确定性规则**: 明确定义标签添加规则和分配逻辑

**标签规则示例**：
```markdown
### windows
Use for any issue that mentions Windows (the OS). Be sure they are saying that they are on Windows.

#### perf
Performance-related issues:
- Slow performance
- High RAM usage
- High CPU usage
**Only** add if it's likely a RAM or CPU issue.
```

### 2. Command 设计模式

Command 是用户可调用的命令，触发特定工作流。

#### Command 文件结构

```markdown
---
description: "命令描述"
model: opencode/kimi-k2.5
subtask: true
---

[命令指令内容]

## GIT DIFF
!`git diff`
```

#### Command 特性

1. **动态内容注入**: 使用 `!`command`` 语法注入命令输出
2. **参数化**: 使用 `$ARGUMENTS` 占位符接收用户输入
3. **子任务标记**: `subtask: true` 标记为子任务

#### Command 示例分析：learn.md

```markdown
---
description: Extract non-obvious learnings from session to AGENTS.md files
---

Analyze this session and extract non-obvious learnings to add to AGENTS.md files.

What counts as a learning (non-obvious discoveries only):
- Hidden relationships between files or modules
- Execution paths that differ from how code appears
- Non-obvious configuration, env vars, or flags
- Debugging breakthroughs when error messages were misleading

What NOT to include:
- Obvious facts from documentation
- Standard language/framework behavior
- Things already in an AGENTS.md
```

**设计要点**：
1. **明确边界**: 清晰定义什么应该/不应该包含
2. **作用域指导**: 指导如何选择放置位置
3. **简洁原则**: 保持条目 1-3 行

### 4. 工具定义模式

工具使用 TypeScript 定义，提供类型安全的接口。

#### 工具定义示例：github-triage.ts

```typescript
export default tool({
  description: `Use this tool to assign and/or label a GitHub issue.`,
  args: {
    assignee: tool.schema
      .enum(ASSIGNEES as [string, ...string[]])
      .describe("The username of the assignee")
      .default("rekram1-node"),
    labels: tool.schema
      .array(tool.schema.enum(["nix", "opentui", "perf", ...]))
      .describe("The labels(s) to add to the issue")
      .default([]),
  },
  async execute(args) {
    // 实现逻辑
  },
})
```

**设计要点**：
1. **Schema 验证**: 使用 Zod-like schema 验证参数
2. **默认值**: 提供合理的默认值
3. **描述文档**: 参数和工具都有清晰的描述

## 配置系统

### opencode.jsonc 配置文件

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "opencode": {
      "options": {},
    },
  },
  "permission": {
    "edit": {
      "packages/opencode/migration/*": "deny",
    },
  },
  "mcp": {},
  "tools": {
    "github-triage": false,
    "github-pr-search": false,
  },
}
```

**配置项说明**：
| 配置项 | 作用 |
|--------|------|
| provider | 模型提供商配置 |
| permission | 文件编辑权限控制 |
| mcp | MCP 服务器配置 |
| tools | 工具启用/禁用 |

## 设计原则提炼

### 原则 1: 单一职责

每个 Agent/Command 只负责一个明确的任务：
- `triage.md` 只负责 Issue 分类
- `translator.md` 只负责翻译
- `docs.md` 只负责文档编写

### 原则 2: 工具隔离

通过工具权限控制，确保 Agent 只能访问必要的工具：
```yaml
tools:
  "*": false           # 禁用所有工具
  "github-triage": true # 只启用特定工具
```

### 原则 3: 确定性规则

为 AI 提供明确的判断规则，减少歧义：
```markdown
**Only** add if it's likely a RAM or CPU issue. **Do not** add for LLM slowness.
```

### 原则 4: 知识分层

将知识按作用域分层存储：
- 项目通用规范 → 根目录 AGENTS.md
- 包特定知识 → packages/*/AGENTS.md
- 任务特定指令 → agent/*.md

### 原则 5: 渐进式上下文

通过分层加载，按需提供上下文：
1. 首先加载根目录 AGENTS.md
2. 根据访问路径加载父目录 AGENTS.md
3. 触发特定任务时加载对应的 Agent/Command

## 与 OpenClaw 对比

| 特性 | OpenCode | OpenClaw |
|------|----------|----------|
| Agent 定义 | `.opencode/agent/` | `.pi/prompts/` |
| 技能定义 | `.opencode/command/` | `skills/*/SKILL.md` |
| 知识文件 | AGENTS.md | AGENTS.md |
| 工具定义 | TypeScript | TypeScript |
| 元数据格式 | YAML Frontmatter | YAML Frontmatter |
| 翻译支持 | 内置术语表系统 | 无内置 |

## 可借鉴点

1. **工具隔离机制**: 通过配置控制 Agent 可用的工具
2. **确定性规则**: 为 AI 提供明确的判断标准
3. **知识累积**: `learn` 命令自动提取会话学习
4. **翻译系统**: 完善的术语表和多语言支持
5. **权限控制**: 文件级别的编辑权限管理
