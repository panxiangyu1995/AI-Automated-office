# AI Agent 提示词模板参考

本文档提供可直接使用的提示词模板，基于 OpenCode 和 OpenClaw 的设计模式总结。

## 模板 1: AGENTS.md 项目级模板

```markdown
# [项目名称] 项目规范

## 项目概述

[一句话描述项目定位和目标]

## 核心原则

### [原则名称]
- [具体规则1]
- [具体规则2]

## 模块结构

- `src/core/` - [模块描述]
- `src/agents/` - [模块描述]
- `src/tools/` - [模块描述]

## 编码规范

### [语言] 规范
- [规范1]
- [规范2]

### 文件命名
- Agent: `*.agent.ts`
- Skill: `*.skill.ts`
- Tool: `*.tool.ts`

## 测试规范

- 单元测试: `*.test.ts`

- E2E 测试: `*.e2e.test.ts`

- [禁止事项1]
- [禁止事项2]
- [禁止事项3]
```

## 模板 6: 工具定义模板 (TypeScript)

```typescript
import { tool } from "[tool-framework]"

export default tool({
  name: "[tool-name]",
  description: `[工具描述]`,
  args: {
    [arg1]: tool.schema
      .string()
      .describe("[参数描述]")
      .default("[默认值]"),
    [arg2]: tool.schema
      .enum(["option1", "option2"] as const)
      .describe("[参数描述]"),
    [arg3]: tool.schema
      .array(tool.schema.string())
      .describe("[参数描述]")
      .default([]),
  },
  async execute(args, context) {
    // 1. 参数验证
    // 2. 执行操作
    // 3. 返回结果
    return {
      success: true,
      data: {},
      message: "[结果消息]"
    }
  },
})
```

## 模板 10: 知识累积模板

```markdown
## 知识提取指南

### 应提取的知识类型

| 类型 | 示例 | 存放位置 |
|------|------|----------|
| 隐藏关系 | [示例] | [位置] |
| 配置陷阱 | [示例] | [位置] |
| 调试突破 | [示例] | [位置] |
| API 怪癖 | [示例] | [位置] |

### 不应提取的内容

- ❌ 文档中已有的明显事实
- ❌ 标准语言/框架行为
- ❌ 已存在于 AGENTS.md 的内容
- ❌ 会话特定细节

### 提取流程

1. 分析会话内容
2. 识别非显而易见的学习
3. 确定作用域
4. 写入对应 AGENTS.md
5. 保持条目简洁 (1-3行)

### 条目格式

```markdown
- [知识点]: [简要说明]
```
```

2. 使用模板 7 创建配置文件
3. 使用模板 9 定义安全护栏

## 最佳实践

### DO ✅

- 保持描述简洁，控制在 1-2 句话
- 使用代码示例代替冗长解释
- 明确边界条件（USE/DON'T USE）
- 提供具体的错误示例
- 分层组织知识内容

### DON'T ❌

- 不要过度解释 AI 已知的概念
- 不要使用模糊的触发条件
- 不要在多个地方重复相同内容
- 不要忽略安全约束
- 不要创建不必要的文档文件
