# CLI-Anything 架构设计

## 核心组件详解

### 1. CLI 入口 (Click 框架)

每个 CLI 使用 Click 框架构建，提供：

**主命令组**：
```python
@click.group(invoke_without_command=True)
@click.option("--json", "use_json", is_flag=True, help="Output as JSON")
@click.option("--project", "project_path", type=str, default=None)
@click.pass_context
def cli(ctx, use_json, project_path):
    """Software CLI — Stateful editing from the command line."""
    global _json_output
    _json_output = use_json

    if project_path:
        sess = get_session()
        if not sess.has_project():
            proj = proj_mod.open_project(project_path)
            sess.set_project(proj, project_path)

    if ctx.invoked_subcommand is None:
        ctx.invoke(repl, project_path=None)
```

**命令分组**：
```python
@cli.group()
def project():
    """Project management commands."""
    pass

@cli.group()
def track():
    """Track management commands."""
    pass

@cli.group()
def effect():
    """Effect management commands."""
    pass
```

**关键设计点**：
- `invoke_without_command=True`：无子命令时进入 REPL
- `--json` 标志：全局输出格式控制
- `--project` 选项：自动加载项目文件

### 3. Session 管理器

状态管理的核心，实现撤销/重做功能：

**数据结构**：
```python
class Session:
    MAX_UNDO = 50
    
    def __init__(self):
        self.project: Optional[Dict[str, Any]] = None
        self.project_path: Optional[str] = None
        self._undo_stack: List[Dict[str, Any]] = []
        self._redo_stack: List[Dict[str, Any]] = []
        self._modified: bool = False
```

**快照机制**：
```python
def snapshot(self, description: str = "") -> None:
    """在变更前保存当前状态到撤销栈"""
    if self.project is None:
        return
    state = {
        "project": copy.deepcopy(self.project),
        "description": description,
        "timestamp": datetime.now().isoformat(),
    }
    self._undo_stack.append(state)
    if len(self._undo_stack) > self.MAX_UNDO:
        self._undo_stack.pop(0)
    self._redo_stack.clear()
    self._modified = True
```

**撤销/重做**：
```python
def undo(self) -> Optional[str]:
    """撤销最后操作"""
    if not self._undo_stack:
        raise RuntimeError("Nothing to undo.")
    
    # 保存当前状态到重做栈
    self._redo_stack.append({
        "project": copy.deepcopy(self.project),
        "description": "redo point",
        "timestamp": datetime.now().isoformat(),
    })
    
    # 恢复前一个状态
    state = self._undo_stack.pop()
    self.project = state["project"]
    return state.get("description", "")
```

**文件锁定保存**：
```python
def _locked_save_json(path, data, **dump_kwargs) -> None:
    """原子写入 JSON，使用独占文件锁"""
    try:
        f = open(path, "r+")  # 打开时不截断
    except FileNotFoundError:
        os.makedirs(os.path.dirname(os.path.abspath(path)), exist_ok=True)
        f = open(path, "w")
    with f:
        _locked = False
        try:
            import fcntl
            fcntl.flock(f.fileno(), fcntl.LOCK_EX)
            _locked = True
        except (ImportError, OSError):
            pass  # Windows / 不支持的文件系统
        try:
            f.seek(0)
            f.truncate()  # 在锁内截断
            json.dump(data, f, **dump_kwargs)
            f.flush()
        finally:
            if _locked:
                fcntl.flock(f.fileno(), fcntl.LOCK_UN)
```

### 4. Backend 抽象层

封装对实际软件的调用：

**典型实现** (LibreOffice)：
```python
# utils/lo_backend.py

def find_libreoffice() -> str:
    """查找 LibreOffice 可执行文件"""
    candidates = [
        "libreoffice",
        "soffice",
        "/usr/bin/libreoffice",
        "/Applications/LibreOffice.app/Contents/MacOS/soffice",
        "C:\\Program Files\\LibreOffice\\program\\soffice.exe",
    ]
    for cmd in candidates:
        path = shutil.which(cmd)
        if path:
            return path
    raise RuntimeError(
        "LibreOffice not found. Install with:\n"
        "  Ubuntu/Debian: sudo apt install libreoffice\n"
        "  macOS: brew install --cask libreoffice\n"
        "  Windows: winget install TheDocumentFoundation.LibreOffice"
    )

def convert_odf_to(odf_path, output_format, output_path=None, overwrite=False):

        odf_path
    ], check=True)
    return {"output": final_path, "format": output_format}

**设计原则**：
- 使用 `shutil.which()` 查找可执行文件

def add_track(project: dict, name: str = None, 
              volume: float = 1.0, pan: float = 0.0) -> dict:
    """添加新音轨"""
    if volume < 0 or volume > 2:
        raise ValueError(f"Volume must be 0-2, got {volume}")
    if pan < -1 or pan > 1:
        raise ValueError(f"Pan must be -1 to 1, got {pan}")
    
    track = {
        "name": name or f"Track {len(project['tracks'])}",
        "type": "audio",
        "volume": volume,
        "pan": pan,
        "mute": False,
        "solo": False,
        "clips": [],
        "effects": [],
    }
    project["tracks"].append(track)
    return track

def remove_track(project: dict, index: int) -> None:
    """移除音轨"""
    if index < 0 or index >= len(project["tracks"]):
        raise IndexError(f"Track index {index} out of range")
    project["tracks"].pop(index)
```

## 设计模式

### 1. 命令模式 (Command Pattern)

每个 CLI 命令封装一个操作：

```
用户输入 → Click 解析 → 命令函数 → Session 快照 → Core 执行 → 输出结果
```

### 2. 状态模式 (State Pattern)

Session 管理器维护项目状态：

```
┌─────────┐    snapshot()    ┌──────────┐
│ Current │ ───────────────▶ │ Undo     │
│ State   │                  │ Stack    │
└─────────┘                  └──────────┘
     ▲                            │
     │         undo()             │
     └────────────────────────────┘
```

### 3. 策略模式 (Strategy Pattern)

Backend 抽象允许不同的实现策略：

```python
# 策略 1: 直接调用软件 CLI
def render_with_sox(project, output):
    subprocess.run(["sox", ...])

# 策略 2: 使用 Python 库
def render_with_pydub(project, output):
    from pydub import AudioSegment
    ...

# 策略 3: 生成脚本文件
def render_with_script(project, output):
    with open("render.py", "w") as f:
        f.write(generate_script(project))
    subprocess.run(["python", "render.py"])
```

### 4. 外观模式 (Facade Pattern)

CLI 提供统一的接口，隐藏底层复杂性：

```
┌─────────────────────────────────────┐
│           CLI Interface              │
│  project new / track add / export   │
└──────────────┬──────────────────────┘
               │
    ┌──────────┼──────────┐
    ▼          ▼          ▼
┌────────┐ ┌────────┐ ┌────────┐
│ Core   │ │Backend │ │ Session│
│ Modules│ │ Layer  │ │ Manager│
└────────┘ └────────┘ └────────┘
```

## 数据流

### 命令执行流程

```
1. 用户输入命令
   ↓
2. Click 解析参数
   ↓
3. 获取/创建 Session
   ↓
4. 检查项目状态
   ↓
5. 创建快照 (如果是变更操作)
   ↓
6. 调用 Core 模块执行
   ↓
7. 更新项目状态
   ↓
8. 格式化输出 (JSON/人类可读)
   ↓
9. 返回结果
```

## 总结

CLI-Anything 的架构设计体现了以下原则：

1. **分层清晰**：CLI → Session → Core → Backend → Software
2. **职责单一**：每个组件专注于特定功能
3. **可扩展性**：通过 Backend 抽象支持任意软件
4. **一致性**：统一的命令结构和输出格式
5. **可靠性**：完善的错误处理和状态管理

这种架构使得添加新软件支持变得简单，同时保证了所有 CLI 的一致体验。
