# UX Design Specification - AI-Automated-office

**Author:** PAN
**Date:** 2026-03-11

---

## Executive Summary

### 项目愿景

**AI-Automated-office** 是一款 **AI 赋能的 ERP 系统**，采用部门化架构设计。核心价值在于：

- 每个部门都有专属 AI 助手
- 跨部门数据自动联动
- 统一数据中台，打破数据孤岛
- 企业只需开通对应部门模块即可

**差异化核心：**
> *"钉钉/飞书给企业一堆工具，企业自己拼凑流程；我们给企业一个 AI 赋能的 ERP，看企业有哪些部门，就提供哪些部门的 AI 能力。"*

### 目标用户

| 角色 | 场景 | 核心痛点 | 期望价值 |
|------|------|----------|----------|
| **财务小李** | 发票处理、台账生成 | 手动录入耗时、易出错 | OCR 自动识别，效率提升 4 倍 |
| **销售小王** | 报价、订单、客户跟进 | 碎片化操作，时间被杂务占用 | 销售自动化，专注大客户 |
| **老板张总** | 经营分析、决策支持 | 数据滞后，不知道下面在做什么 | 实时看板，提前预警 |
| **售后老陈** | 工单处理、经验传承 | 经验在脑子里，新人总要问 | 知识沉淀，智能问答 |
| **招标小刘** | 标书制定、资质管理 | 时间紧、格式繁琐 | AI 辅助生成，模板库 |
| **管理员阿明** | 权限管理、系统维护 | 多系统账号权限混乱 | 统一管理，插件化扩展 |
| **开发者小张** | 定制化开发 | 重复造轮子 | 插件化复用 |
| **新员工小赵** | 入职适应 | 系统陌生，不敢问人 | AI 引导，自助学习 |

### 核心功能模块

| 分类 | 模块 | 核心能力 |
|------|------|----------|
| **核心部门** | 人事部、审批中心、销售部、财务部、仓储部、管理层 | 内置不可卸载 |
| **扩展部门** | 售后服务、招投标、市场宣传 | 按需安装 |
| **平台能力** | AI Agent 框架、部门权限系统、统一消息系统、知识库 RAG | 底层支撑 |

### 关键设计挑战

**1. 部门化架构的认知负荷**
- 用户需要理解"部门模块"概念
- 如何让用户自然地感知"我的部门有什么功能"
- 跨部门数据联动的可视化表达

**2. AI 与工具调用的透明性**
- 用户需要看到 AI 在做什么、调用了什么工具
- 失败时的重试、纠偏、手动干预机制
- 敏感操作的用户确认体验

**3. 桌面端复杂信息架构**
- 多部门、多功能的导航组织
- AI 对话区与传统功能界面的融合
- 数据看板与工作台的设计

**4. 用户能力差异**
- 从老板（管理视角）到新员工（执行视角）
- 从技术用户（开发者）到业务用户（财务、销售）
- 同一界面如何适应不同角色的需求

### 设计机会

| 机会 | 说明 |
|------|------|
| **AI 优先的工作流** | 将 AI 助手作为核心入口，传统 UI 作为补充 |
| **上下文感知导航** | 根据用户角色和当前任务动态调整界面 |
| **渐进式复杂度** | 新用户简单引导，高级用户深度功能 |
| **跨部门协作可视化** | 让用户直观看到数据如何跨部门流动 |

## 核心用户体验

### 定义性体验

**核心超能力：** 和 AI 说话就能完成任务

用户通过自然语言对话作为主要交互方式，AI 理解意图并调用相应工具完成任务。这一定位决定了：

- AI 对话面板是产品的**主入口**，而非辅助功能
- 传统菜单和表单 UI 是**补充入口**，为高级用户提供快捷方式
- 用户无需学习复杂的操作路径，只需"说出来"

**交互模式：透明 + 可控**

- **透明**：用户可以实时看到 AI 调用了哪些工具、参数是什么、结果如何
- **可控**：用户可以随时介入、调整参数、重试、或手动完成

### 平台策略

| 维度 | 决策 |
|------|------|
| **主平台** | 桌面端 |
| **使用场景** | 办公室桌面电脑，大屏幕 |
| **移动端** | Post-MVP 规划 |
| **离线能力** | 支持本地功能使用 |

### 轻松交互

**零学习成本设计目标：**

- 用户无需培训即可上手
- 适应各种电脑水平的用户（从新手到老员工）
- 减少操作步骤，消除"不知道该点什么"的困惑

**傻瓜式操作原则：**

| 用户痛点 | 设计应对 |
|----------|----------|
| 不知道点什么按钮 | AI 引导 + 自然语言交互 |
| 填错表单不知道怎么改 | AI 智能纠偏 + 一键修复 |
| AI 回复看不懂 | 简洁语言 + 可视化结果 |
| 交互复杂 | 减少步骤，一键完成 |

### 关键成功时刻

**老板张总看到数据看板的那一刻：**

- 完善的仪表系统，关键数据一目了然
- 每个部门有独立的数据统计展示面板
- 新插件加入不影响现有看板布局
- 打开即有价值，无需配置

**设计目标：** 让老板在第一眼就感受到"这正是我需要的"。

### 体验原则

| # | 原则 | 说明 |
|---|------|------|
| **1** | **AI 即入口** | 对话是主交互方式，传统 UI 是补充 |
| **2** | **透明可控** | 用户永远知道 AI 在做什么，可以随时介入调整 |
| **3** | **零学习成本** | 傻瓜式操作，适应各种电脑水平 |
| **4** | **即时价值** | 打开就有用，第一眼就震撼 |
| **5** | **插件化扩展** | 新部门加入不影响现有体验 |

## 期望情感响应

### 核心情感目标

用户在使用产品时应感受到三种核心情感：

| 情感 | 说明 | 设计含义 |
|------|------|----------|
| **省心** | 不用操心细节，AI 帮你处理 | 自动化 + 智能推理 |
| **掌控感** | 一切尽在掌握 | 透明 + 关键确认 |
| **变厉害** | 效率提升，能力放大 | 成就反馈 + 数据可视化 |

### 避免的负面情感

**核心负面情感：用户觉得 AI 不可控**

**触发原因：** AI 做了用户不知道的事情

**设计对策：**
- 所有工具调用过程透明可见
- 重要步骤需要用户确认
- 用户可随时查看 AI 的操作日志

### 确认策略

| 操作类型 | 确认策略 |
|----------|----------|
| **日常操作** | 轻度知情，AI 告诉用户在做什么 |
| **重要操作** | 需要点一下确认 |
| **敏感操作** | 二次确认（如删除、审批、合同签订） |

### 成就反馈机制

让用户感受到"变厉害了"：

| 反馈类型 | 示例 |
|----------|------|
| **时间节省** | "这个任务原本需要 2 小时，现在 5 分钟" |
| **效率对比** | "本月效率提升 40%" |
| **完成数量** | "您本月处理了 156 张发票" |
| **成功反馈** | "✅ 台账已生成" |

### 情感旅程设计

| 阶段 | 期望情感 | 设计目标 |
|------|----------|----------|
| **首次打开** | 惊喜、震撼 | 看板一目了然，即时价值 |
| **尝试 AI 对话** | 好奇、被理解 | AI 懂我，响应准确 |
| **完成任务** | 成就感、轻松 | 原来这么简单 |
| **出问题时** | 安心、有信心 | 清楚发生了什么，有解决办法 |
| **下次使用** | 期待、信任 | 想用它，离不开它 |

### 情感设计原则

| # | 原则 | 说明 |
|---|------|------|
| **1** | **透明优先** | 用户永远知道 AI 在做什么 |
| **2** | **关键确认** | 重要操作需用户确认，建立信任 |
| **3** | **成就可见** | 让用户看到自己的进步和效率提升 |
| **4** | **失败不恐慌** | 出错时有清晰指引，用户可解决 |

## UX 模式分析与灵感

### 灵感产品分析

**目标用户常用产品：**
- 钉钉、飞书（办公协作）
- 金蝶（财务工具）
- Excel（灵活数据处理）

**做得好的方面：**
- 规范化、流程化

**痛点：**
- 入口难找、步骤太多、表单繁琐
- 发票录入繁琐、对账复杂
- 部分功能需要依赖 Excel 补充

### 可迁移的 UX 模式

| 模式 | 来源 | 应用场景 |
|------|------|----------|
| **对话驱动** | ChatGPT、Claude | AI 对话面板作为主入口 |
| **插件化布局** | VSCode | 类似 VSCode 的可定制面板布局 |
| **工具调用可视化** | Cursor、Windsurf | 显示 AI 调用了什么工具、结果如何 |
| **数据看板** | Power BI、飞书多维表格 | 每个部门独立看板，一目了然 |
| **渐进式披露** | Apple 设计原则 | 简单先展示，复杂按需展开 |

### 要避免的反模式

| 反模式 | 说明 | 我们的应对 |
|--------|------|----------|
| **功能堆砌** | 像钉钉那样塞太多功能入口 | AI 对话替代菜单导航 |
| **强制流程** | 用户必须按固定步骤操作 | 一句话触发，AI 自动执行 |
| **黑盒 AI** | AI 悄悄做事用户不知道 | 透明 + 关键确认 |
| **过度限制** | 限制用户的自定义需求 | 支持自定义 + Excel 导出 |

### 设计灵感策略

| 维度 | 策略 | 说明 |
|------|------|------|
| **入口** | AI 对话替代菜单导航 | 不用"找功能"，直接"说需求" |
| **步骤** | 一句话触发，AI 自动执行 | 减少步骤，甚至零步骤 |
| **表单** | AI 智能填充 + 语音/图片输入 | 不用手动填表 |
| **发票录入** | OCR 自动识别 | 上传图片即可 |
| **对账** | AI 自动匹配 + 异常提示 | 系统自动处理，人只看异常 |
| **灵活性** | 支持自定义 + Excel 导出 | 不限制用户需求 |

**核心理念：** 保留"流程化、规范化"的价值，用 AI 让操作变简单。

## 设计系统基础

### 设计系统选择

**选定方案：Shadcn/ui + Tailwind CSS**

| 维度 | 说明 |
|------|------|
| **核心框架** | React + TypeScript |
| **UI 组件库** | Shadcn/ui（可复制、可修改） |
| **样式方案** | Tailwind CSS |
| **图标库** | Lucide React（或自定义） |

### 选择理由

| 考量因素 | 决策依据 |
|----------|----------|
| **技术栈匹配** | 团队熟悉 React，Shadcn/ui 基于 React |
| **品牌独特性** | 组件可复制修改，支持完全定制 |
| **品牌规范对接** | 支持自定义设计令牌（颜色、字体、间距等） |
| **开发效率** | 复制即用，无需 npm 依赖管理 |
| **维护成本** | 代码在项目中，完全可控 |
| **桌面端适配** | Tailwind 灵活，适合 Desktop App Web 层 |

### 实施方法

**阶段 1：设计令牌定义**
- 基于现有品牌规范，定义颜色、字体、间距、圆角等令牌
- 在 Tailwind 配置中实现令牌系统

**阶段 2：基础组件定制**
- 复制 Shadcn/ui 组件到项目
- 根据品牌规范调整组件样式
- 建立组件文档和 Storybook

**阶段 3：扩展组件开发**
- 开发业务特定组件（AI 对话面板、工具调用卡片等）
- 建立插件化布局组件系统

### 定制化策略

| 定制领域 | 策略 |
|----------|------|
| **颜色系统** | 基于品牌主色定义语义化颜色（primary、success、warning、error） |
| **字体系统** | 定义标题、正文、代码等字体规范 |
| **组件风格** | 调整圆角、阴影、边框等，匹配品牌调性 |
| **动效系统** | 定义过渡、动画时长和缓动函数 |
| **图标系统** | 统一图标风格，或自定义图标库 |

## 核心交互定义

### 定义性体验

**核心交互：** 和 AI 说话就能完成任务

用户只需用自然语言说出需求，AI 理解意图、调用工具、完成工作。这个交互模式决定了：
- AI 对话面板是产品的**主入口**
- 传统菜单和表单 UI 是**补充入口**
- 用户无需学习复杂的操作路径，只需"说出来"

**交互模式特点：**
- 用户已熟悉 ChatGPT 式对话交互
- "对话 → 工具调用 → 完成任务"是新模式
- 需要设计"工具调用过程"的用户体验

### 用户心智模型

| 场景 | 当前方式 | 期望方式 |
|------|----------|----------|
| 财务处理发票 | 打开金蝶 → 找功能 → 填表单 | 对 AI 说"处理这些发票" |
| 老板看数据 | 问下面人 → 等报表 → 看 Excel | 打开看板一目了然 |
| 审批流程 | 找管理员配置 → 设置节点 → 测试 | 对 AI 说"帮我建一个请假审批" |

### 成功标准

| 维度 | 标准 |
|------|------|
| **速度** | 几秒内开始响应 |
| **准确** | 第一次就做对（或容易修改） |
| **透明** | 用户知道 AI 在做什么 |
| **可控** | 不满意可以调整 |
| **审核** | 关键操作需用户确认后才生效 |

### 交互模式分析

**新颖性评估：**
- 对话交互：用户已熟悉（ChatGPT 模式）
- 工具调用：新模式，需要设计用户体验

**设计策略：**
- 对话部分：沿用熟悉的 ChatGPT 式交互
- 工具调用：设计透明、可控的调用面板
- 结果确认：设计审核流程，关键操作需用户确认

### 核心交互流程

**场景：批量处理发票**

| 步骤 | 用户行为 | 系统响应 |
|------|----------|----------|
| 1. 发起 | 指向文件夹 + 说"处理里面的发票" | 显示"正在扫描文件夹..." |
| 2. 识别 | 无（等待） | OCR 批量识别 → 显示进度 |
| 3. 预览 | 滚动查看提取信息 + 原文件对照 | 左右分栏：提取信息 / 原文件预览 |
| 4. 审核 | 逐项检查：发票信息、科目、金额、抬头 | 显示审核状态 |
| 5. 修改 | 直接编辑 或 对 AI 说修改 | 实时更新提取信息 |
| 6. 确认 | 点击"确认录入" | 写入数据库 → 显示成功 |

**关键设计点：**
- 生成和录入是两个独立步骤
- 生成后用户可预览、修改
- 只有用户确认后才真正写入系统
- 批量场景支持左右对照、滚动查看

### 检查点与回滚交互

**目标体验：** 用户在对话内随时可见检查点，支持一键回滚或编辑重试。

**展示位置：**
- 每条用户消息上方自动生成检查点标记线
- 标记线包含时间、输入摘要与状态图标

**核心操作：**
- 恢复对话：仅回滚对话与AI记忆，保留文件变更
- 恢复对话与文件：回滚对话、记忆与文件变更
- 编辑重试：将该条输入填入输入框，生成分支对话

**交互流程：**
1. 用户发送消息 → 自动生成检查点标记
2. 用户点击标记 → 打开检查点详情卡片
3. 选择“恢复对话”或“恢复对话与文件”
4. 系统弹出确认对话框，显示影响范围与将被撤销的内容
5. 执行回滚，提示成功并在对话流中插入状态提示条

**检查点详情卡片内容：**
- 创建时间
- 用户输入摘要
- 文件变更摘要
- 对话分支信息（如有）

### 上下文压缩与关键事实提示

**目标体验：** 用户理解上下文使用情况，并可感知压缩后的关键事实。

**展示位置：**
- 输入框上方显示“关键事实”条目（3-5条）
- 对话顶部显示上下文使用率指示器

**核心操作：**
- 查看摘要：点击“上下文摘要”打开详情
- 事实管理：支持置顶、删除或标记为过期
- 手动压缩：提供“立即压缩”入口（可选）

**交互流程：**
1. 系统实时显示上下文使用率（百分比+进度条）
2. 超过阈值时提示“建议压缩”
3. 系统生成摘要并提取关键事实
4. 对话流中插入“压缩完成”提示条，附摘要入口
5. 关键事实展示在输入框上方，支持轻量管理

**状态提示：**
- 进行中：显示“正在压缩”并标注预计耗时
- 完成：显示摘要入口与关键事实条目
- 失败：提示原因并允许重试

### 审核界面设计

**批量审核界面模式：**

| 模式 | 适用场景 | 特点 |
|------|----------|------|
| **左右分栏对照** | 大批量审核 | 左侧列表 + 右侧原文件预览，滚动联动 |
| **卡片列表对照** | 中小批量审核 | 每张发票一个卡片，缩略图 + 提取信息并排 |

**审核内容清单：**
- 发票信息是否准确
- 科目分类是否正确
- 金额是否匹配
- 公司抬头是否正确

**修改方式：**
- 直接编辑字段
- 对 AI 说"把金额改成 5000"

## 设计方向决策

### 参考设计

**核心参考：** VSCode UI 布局

VSCode 的布局结构：
- **活动栏（最左侧）**：一列图标（48px），快速切换侧边栏视图
- **侧边栏（左侧）**：可折叠，显示不同视图
- **编辑器区（中间）**：主要工作区，多标签页
- **面板（底部或右侧）**：可折叠，终端/输出等
- **状态栏（最底部）**：状态信息

### 选定布局方案

**AI-Automated-office 采用 VSCode 风格四栏布局：**

```
┌─────────────────────────────────────────────────────────────────────┐
│                              顶部工具栏                              │
├────┬────────────────┬──────────────────────────┬────────────────────┤
│活动栏│    侧边栏     │         工作区            │    AI 对话面板     │
│48px│ 200-280px     │        自适应              │    300-500px      │
│固定│   可折叠      │                          │     可折叠         │
├────┴────────────────┴──────────────────────────┴────────────────────┤
│                              状态栏                                  │
└─────────────────────────────────────────────────────────────────────┘
```

| 区域 | 位置 | 内容 | 特点 |
|------|------|------|------|
| **活动栏** | 最左侧 48px | 部门图标快捷入口 | 固定，图标列表 |
| **侧边栏** | 左侧 200-280px | 部门模块树、工具状态、消息通知 | 可折叠 |
| **工作区** | 中间主区域 | 数据看板/列表/表单 | 自适应宽度 |
| **AI 对话面板** | 右侧 300-500px | AI 对话 + 工具调用面板 | 可折叠 |
| **状态栏** | 最底部 | 状态信息、快捷操作 | 固定 |

### 设计理由

1. **用户熟悉**：VSCode 布局被广泛认知，降低学习成本
2. **灵活可定制**：各面板可折叠、可调整大小
3. **插件化友好**：活动栏图标对应部门模块，符合插件化架构
4. **信息层级清晰**：活动栏 → 侧边栏 → 工作区 → AI 面板，逐级展开
5. **AI 对话突出**：右侧面板位置醒目，符合"AI 即入口"理念

## 用户旅程流程

### 关键旅程选择

基于 PRD 中定义的 8 个用户旅程，选择以下 3 个关键旅程设计详细流程：

| # | 旅程 | 选择理由 |
|---|------|----------|
| **1** | 财务小李 - 发票处理 | 最能体现 AI 对话 + 工具调用 + 审核确认 |
| **2** | 老板张总 - 数据看板 | 关键成功时刻，第一印象决定成败 |
| **3** | 新员工小赵 - 入职引导 | 零学习成本体验，新用户引导 |

### 旅程 1：财务小李 - 发票处理

**场景：** 小李需要处理一叠发票，生成台账

**流程步骤：**

| 步骤 | 用户行为 | 系统响应 |
|------|----------|----------|
| 1. 发起 | 拖拽发票到对话区 / 输入"处理这个文件夹的发票" | 显示"正在识别..." |
| 2. 识别 | 无（等待） | 批量 OCR 识别，显示进度 |
| 3. 预览 | 滚动查看提取信息 + 原文件对照 | 左侧列表 + 右侧预览 |
| 4. 审核 | 逐项检查：发票信息、科目、金额、抬头 | 显示审核状态 |
| 5. 修改 | 直接编辑 / 对 AI 说修改 | 实时更新提取信息 |
| 6. 确认 | 点击"确认录入" | 写入数据库 → 显示成功 |

**关键设计点：**
- 支持拖拽和对话两种发起方式
- 批量场景支持左右对照、滚动查看
- 生成和录入是两个独立步骤

### 旅程 2：老板张总 - 数据看板

**场景：** 张总打开应用，看到实时经营数据

**流程步骤：**

| 步骤 | 用户行为 | 系统响应 |
|------|----------|----------|
| 1. 打开 | 打开应用 | 自动登录 |
| 2. 识别 | 无 | 识别角色为管理层 |
| 3. 展示 | 无 | 默认显示数据看板 |
| 4. 浏览 | 查看关键指标 | 销售额、应收款、库存、工单 |
| 5. 预警 | 发现异常数据 | 显示预警提示 |
| 6. 深入 | 打开 AI 对话 | 输入问题，AI 生成分析 |

**关键设计点：**
- 根据角色自动显示默认视图
- 关键指标一目了然
- 异常数据自动预警

### 旅程 3：新员工小赵 - 入职引导

**场景：** 小赵第一次登录系统

**流程步骤：**

| 步骤 | 用户行为 | 系统响应 |
|------|----------|----------|
| 1. 登录 | 首次登录 | 检测新用户 |
| 2. 欢迎 | 无 | 显示欢迎引导 |
| 3. 认识界面 | 跟随引导 | 高亮各区域 |
| 4. 第一个任务 | 点击公告 | 显示公告详情 |
| 5. 尝试 AI | 输入问题 | AI 回复建议 |
| 6. 完成 | 无 | 进入正常工作区 |

**关键设计点：**
- 分步骤渐进引导
- 高亮提示界面区域
- 通过实际任务学习

### 旅程模式总结

| 模式 | 说明 | 应用场景 |
|------|------|----------|
| **AI 发起** | 通过 AI 对话触发任务 | 发票处理、报表生成 |
| **自动展示** | 根据角色自动显示内容 | 数据看板、部门工作台 |
| **渐进引导** | 分步骤引导新用户 | 入职引导、功能发现 |
| **检查点回滚** | 从历史节点恢复或分支 | 内容润色、方案探索 |

### 旅程 4：检查点回滚 - 内容润色

**场景：** 用户让AI润色一段文字，但对结果不满意，想回到某个节点重新尝试

**流程步骤：**

| 步骤 | 用户行为 | 系统响应 |
|------|----------|----------|
| 1. 发起润色 | 输入"帮我润色这段文字..." | 创建检查点，显示标记线 |
| 2. 查看结果 | 阅读AI润色后的内容 | 显示润色结果 |
| 3. 不满意 | 点击检查点标记线的"Restore" | 弹出回滚确认弹窗 |
| 4. 选择范围 | 选择"仅恢复对话" | 保留文件变更 |
| 5. 确认回滚 | 点击"确认恢复" | 执行回滚，恢复对话状态 |
| 6. 重新润色 | 修改输入，添加新要求 | AI重新润色 |

**关键设计点：**
- 检查点自动创建，用户无需手动操作
- 回滚范围可选，给用户灵活控制
- 编辑重试功能支持尝试不同路径

### 旅程 5：检查点分支 - 方案探索

**场景：** 用户想让AI尝试两种不同的方案，比较结果

**流程步骤：**

| 步骤 | 用户行为 | 系统响应 |
|------|----------|----------|
| 1. 发起任务 | 输入"生成一份报价单..." | 创建检查点cp-001 |
| 2. 查看结果 | 阅读AI生成的报价单 | 显示报价单内容 |
| 3. 尝试分支 | 点击检查点的"Retry" | 历史输入填充到输入框 |
| 4. 修改输入 | 修改为"生成报价单，使用美元计价" | 创建分支检查点cp-001-b1 |
| 5. 对比结果 | 在两个分支间切换查看 | 显示两个版本的差异 |

**关键设计点：**
- 分支对话独立维护
- 用户可在分支间切换
- 原对话历史保留作为参考

  - 🟢 绿色 `#22C55E`：0-60%（正常）

- 字体：小号，与输入框高度对齐

**交互行为：**
- 悬停显示详细 Token 数（如：8,240 / 10,000）
- 无需点击交互

## UX 一致性模式

### 按钮层级

| 层级 | 用途 | 样式 |
|------|------|------|
| **主要** | 提交、确认、保存 | 品牌主色背景，白色文字 |
| **次要** | 取消、返回 | 白色背景，主色边框 |
| **文字** | 链接、次要操作 | 无边框，主色文字 |
| **危险** | 删除、清除 | 红色背景，白色文字 |

| 类型 | 场景 | 展示方式 |
|------|------|----------|
| **成功** | 操作成功 | Toast 通知（右上角，3秒自动消失） |
| **错误** | 操作失败 | Toast 通知（红色，需手动关闭） |
| **警告** | 需要注意 | Toast 通知（橙色，5秒自动消失） |
| **信息** | 一般提示 | Toast 通知（蓝色，3秒自动消失） |
| **确认** | 重要操作前 | Dialog 弹窗确认 |
| **进度** | 长时间操作 | Progress 进度条 |

| 元素 | 规范 |

| **验证** | 实时验证，错误信息在输入框下方 |
| **帮助文本** | 灰色小字，在输入框下方 |
| **提交按钮** | 表单底部，主按钮样式 |

- 默认：灰色边框

## 响应式设计与无障碍

### 响应式策略

基于平台策略（桌面端优先，移动端 Post-MVP）：

| 阶段 | 平台 | 策略 |
|------|------|------|
| **MVP** | 桌面端 | 固定宽度面板，支持窗口缩放 |
| **Post-MVP** | 平板/移动端 | 自适应布局 |

**桌面端响应式行为：**

| 场景 | 行为 |
|------|------|
| **全屏模式** | 所有面板展开 |
| **窗口缩小** | 侧边栏可折叠，AI 面板可折叠 |
| **最小宽度** | 1024px，小于此宽度提示用户放大 |

### 断点策略

| 断点 | 宽度 | 布局调整 |
|------|------|----------|
| **大屏** | ≥1440px | 全功能展示，所有面板展开 |
| **标准** | 1024-1439px | 标准布局，面板可折叠 |
| **最小** | <1024px | 提示放大窗口 |

### 无障碍策略

**目标：** WCAG 2.1 Level AA 合规

| 要求 | 标准 | 实现 |
|------|------|------|
| **对比度** | 正文 ≥ 4.5:1 | 深色文字 + 浅色背景 |
| **大标题对比度** | ≥ 3:1 | 已满足 |
| **焦点状态** | 明显的焦点环 | 主色边框 + 阴影 |
| **键盘导航** | 全键盘可操作 | Tab + 快捷键 |
| **触摸目标** | ≥ 44x44px | 按钮最小高度 36px + padding |
| **屏幕阅读器** | 语义化标签 + ARIA | aria-label, role |

## 固定 UI / 混合 UI / 动态 UI 边界补充说明

为了支撑通用 Agent 覆盖所有业务功能，同时保持系统的一致性与可控性，界面必须遵循以下边界：

| 类型 | 适用范围 | 说明 |
|------|----------|------|
| 固定 UI | 登录、设置、权限、插件治理、系统消息、审计、顶层布局 | 平台级、强约束、不可随模板漂移 |
| 混合 UI | 工作台、审批页、详情页、编辑器工作区、部门容器页 | 外层壳层固定，内容区动态 |
| 动态 UI | 业务表单、详情主体、看板、流程视图、文档模板 | 企业差异化最强，由模板或 Schema 驱动 |

### UX 铁律

1. 动态 UI 只能出现在固定壳层或混合壳层内部，不能直接替换全局布局。
2. 审批动作区、系统设置、权限控制、插件管理等系统控制面必须保持固定 UI。
3. 工作台内容区、审批单内容区、详情页主体区、业务模板区优先采用动态 UI。
4. 用户必须能清晰辨认“系统固定壳层”和“Agent/模板驱动内容”的边界。

## Agent 与动态内容区交互规范补充说明

通用 Agent 的输出不应只停留在对话消息中，而应通过受控方式进入工作区内容区。

### 交互约束

1. Agent 生成的结果应优先进入表单区、详情区、模板区或卡片区，供用户审阅和修正。
2. Agent 对页面内容的修改必须可见、可回滚、可确认，不能以黑盒方式直接替换用户界面。
3. 对高风险动作，界面必须在动态内容区之外提供明确确认入口，保持“透明可控”原则。
4. 动态内容区的渲染结果应保留来源标识，明确是模板生成、Agent 填充还是用户手工编辑。
