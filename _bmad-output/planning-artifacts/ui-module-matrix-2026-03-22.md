# AI-Automated-office - 固定 UI / 混合 UI / 动态 UI 模块矩阵（UTF-8）

**Author:** Codex  
**Date:** 2026-03-22  
**用途：** 明确系统中哪些页面应固定、哪些应混合、哪些应动态渲染。

---

## 1. 三层策略

1. 固定 UI：平台治理、安全审计、全局壳层。  
2. 混合 UI：外壳固定，内容区动态。  
3. 动态 UI：企业差异最大的业务承载区。

---

## 2. 判定标准

| 维度 | 固定 UI | 混合 UI | 动态 UI |
|------|---------|---------|---------|
| 跨企业通用性 | 高 | 中 | 低 |
| 安全与审计要求 | 高 | 高 | 中 |
| 布局变化频率 | 低 | 中 | 高 |
| 字段差异程度 | 低 | 中 | 高 |
| 交互一致性要求 | 高 | 高 | 中 |
| 模板化价值 | 低 | 中 | 高 |

## 7. 迁移建议

1. 不重做固定 UI（登录、设置、权限、插件治理、系统配置）。  
2. 优先改造 Workbench 为渲染宿主。  
3. 优先将工作台主体、审批单主体、详情页主体切到动态渲染。  
4. 先完成模板运行时，再大规模推进部门页面动态化。

---

## 8. 结论

最可行的策略是：

**固定平台壳 + 混合业务页 + 动态业务内容区**。

这同时满足平台一致性、企业差异化、权限可控、可测试与可治理。
