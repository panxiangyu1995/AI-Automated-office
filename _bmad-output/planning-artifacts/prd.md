# Product Requirements Document - AI-Automated-office

**Author:** PAN
**Date:** 2026-03-09

## Executive Summary

### 产品愿景

**AI-Automated-office** 是一款**AI赋能的ERP系统**，旨在为企业提供高度集成的部门职能管理平台。每个部门都有专属AI助手，跨部门数据自动联动，实现企业运营的全流程智能化。

**核心理念：** 系统基于"核心部门 + 扩展部门"架构，核心部门（人事、财务、销售、仓库、审批、管理）作为内置功能模块，扩展部门（售后服务、招投标、市场宣传等）按需安装。每个部门模块都配备AI能力，通过部门权限模型实现精细化管理。

**目标用户：** B2B企业客户，覆盖全员使用场景——从一线员工到管理层，不同部门获得差异化的AI能力支持。

**核心问题：**
- 钉钉/飞书等工具提供的是"工具集合"，各部门独立使用，数据孤岛
- 企业需要的是"ERP整合"，跨部门数据联动，全流程AI赋能
- 传统ERP系统僵化，企业需适应软件逻辑，定制成本高

**解决路径：** 部门化架构 + AI赋能，实现：
- 核心部门内置，覆盖企业基本职能
- 扩展部门按需安装，灵活适配企业组织架构
- 跨部门数据联动，统一数据中台
- 每个部门配备AI助手，智能化办公

### 差异化核心

| 维度 | 钉钉/飞书 | 本产品 |
|-----|----------|-------|
| **产品本质** | 工具集合 | **AI赋能ERP** |
| **部门关系** | 各部门独立使用工具 | **跨部门数据联动** |
| **AI定位** | 局部功能增强 | **全流程AI赋能** |
| **数据流** | 各应用数据孤岛 | **统一数据中台** |
| **权限模型** | 应用级权限 | **部门级权限模型** |
| **定制化** | 有限配置 | **部门职能按需扩展** |

**核心洞察：** 
- 钉钉/飞书给企业一堆工具，企业自己拼凑流程
- 我们给企业一个AI赋能的ERP，每个部门都有专属AI助手，跨部门数据自动联动
- 定制化方式：看企业有哪些部门，开通对应部门模块即可

**一句话价值主张：** *"我们不是卖工具，而是为企业构建AI赋能的ERP系统——看您有哪些部门，我们就提供哪些部门的AI能力，数据自动联动，流程无缝衔接。"*

## Product Scope

### 产品架构：核心部门 + 扩展部门

本产品采用**部门化架构**，而非传统的插件架构。每个部门模块都具备完整的职能功能和AI赋能能力。

**架构理念：**
- **核心部门（内置）**：所有企业必备的基础部门，不可卸载
- **扩展部门（可安装）**：按企业实际组织架构按需开通
- **部门权限模型**：用户权限 = 基础权限（人事权限） + 部门权限 + 审批发起权限

### MVP - 最小可行产品

**平台核心：**
- 桌面端UI（类VSCode布局）
- AI Agent框架（工具调用、MCP接入、会话管理、记忆管理、定时任务、心跳机制）
- 部门模块系统（核心部门内置、扩展部门可安装）
- 部门权限系统（部门级权限模型）
- 公告和消息通知系统（系统公告、消息推送、未读提醒、免打扰模式）
- 多租户架构
- 部门市场（扩展部门浏览安装）

**核心部门模块（6个，内置不可卸载）：**

| 部门 | 核心职能 | AI赋能场景 | 依赖关系 |
|-----|---------|-----------|---------|
| **人事部** | 员工管理、部门架构、考勤管理、入职离职 | 智能入职引导、考勤异常预警 | 无（基础层） |
| **审批中心** | 自由流程创建、AI生成流程、审批/驳回、历史记录 | 对话生成审批流程、智能路由、动态数据表生成 | 人事部 |
| **销售部** | 报价单AI生成、合同AI生成、订单处理、销售自动化、客户管理 | AI生成报价单/合同、客户跟进提醒、第三方平台接入 | 人事部 + 仓储部 |
| **财务部** | 发票/合同OCR、台账生成、应收应付、与销售联动（获取报价单/合同） | 智能对账、发票自动识别、财务数据分析 | 人事部 + 销售部 |
| **仓储部** | 入库、出库、库存管理、物流仓储、库存预警 | 库存预警、智能补货建议、物流追踪 | 人事部 |
| **管理层（老板端）** | 数据看板、经营分析、预警机制、跨部门数据汇总 | AI经营洞察、风险预警、决策支持 | 访问所有部门数据接口 |

**扩展部门模块（3个，可安装）：**

| 部门 | 核心职能 | AI赋能场景 | 权限组合 |
|-----|---------|-----------|---------|
| **售后服务部** | 工单管理、维修经验沉淀、客户回访、知识库 | 维修经验自动沉淀、智能问答 | 人事权限 + 售后权限 + 审批发起 |
| **招投标部** | 标书制定、资质管理、投标管理 | AI辅助生成标书、资质到期提醒 | 人事权限 + 招投标权限 + 审批发起 |
| **市场宣传部** | 营销活动、内容管理、数据分析 | AI内容生成、效果分析 | 人事权限 + 市场权限 + 审批发起 |

**知识库RAG** 作为扩展能力，可被多个部门调用（售后、招投标等）。

### 增长期功能（Post-MVP）

## User Journeys

### 旅程 1：财务人员 - 小李

**角色背景：** 小李是一家中型企业的财务专员，负责处理发票、合同、报销单，公司有3个不同的抬头，每个月要处理上千张票据。

#### 开场：痛点初现

周一早上8:30，小李的办公桌上堆满了上周积累的发票和报销单。她叹了口气，打开Excel，准备开始手动录入。这已经是她连续第三周加班了——每到月底，她都要花整整一周时间整理票据、核对金额、生成台账，然后还要应付老板随时可能问的"这个月我们付了多少款？应收还有多少？"

她最怕的是：**录错一个数字，整个台账都要重查。**

#### 上升行动：遇见改变

公司引入了AI-Automated-office。小李第一次打开软件时，有些怀疑——"又是一个工具？"

她按照引导，安装了**财务OCR插件**。然后尝试把一叠发票放在扫描仪前，点击"批量识别"。

**30分钟后**——她惊呆了。

- 发票信息自动识别，准确率98%
- 自动匹配公司抬头
- 自动分类（增值税发票、普通发票、报销单）
- 一键生成台账，导出Excel

她原本要花**2天**的工作，现在**半小时**搞定了。

#### 高潮：价值时刻

月底，老板突然问："小李，这个月应付账款是多少？"

以前，小李会说："张总，我查一下，下午给您。"

现在，她打开**数据看板**，实时数据一目了然："张总，本月应付账款186万，其中已付120万，待付66万，主要供应商是..."

老板点点头："很好，这个系统不错。"

小李心里想：**"我终于可以准时下班了。"**

#### 结局：新现实

- 工作时间：从每周加班3天 → 准时下班
- 错误率：从每月5-10处 → 几乎为0
- 老板满意度：从"怎么又错了" → "效率很高"

### 旅程 2：销售人员 - 小王

**角色背景：** 小王是公司的销售，除了维护老客户，他还在闲鱼上挂了一些公司的二手设备。每次成交后，他要手动联系仓库发货、记录销售数据、月底汇报。

#### 开场：碎片化的一天

小王的手机响了——闲鱼又有人下单了。他放下手头的工作，开始回复消息、记录订单、打电话给仓库老陈确认库存...

一天下来，他感觉自己像个"打杂的"，真正谈客户的时间反而很少。

#### 上升行动：自动化魔法

公司上线了AI-Automated-office，小王安装了**销售自动化插件**。

他发现可以把闲鱼消息接入系统，设置自动回复规则：
- "成交"关键词 → 自动生成订单
- 自动通知仓库发货
- 自动更新销售数据

**第一次测试：** 一个客户在闲鱼问"这个还在吗？多少钱？"

系统自动回复，客户下单，仓库收到提醒，打包发货——**小王全程没有介入。**

#### 高潮：效率革命

月底，小王打开**数据看板**：

- 本月闲鱼成交：47单
- 自动处理率：92%
- 发货及时率：100%
- 总销售额：12.6万

老板看到数据后说："小王，你这个月销售数据不错啊，怎么做到的？"

小王笑了："系统帮我干了很多事，我可以专心谈大客户了。"

#### 结局：新现实

- 日常杂务时间：减少70%
- 销售转化率：提升30%（有更多时间跟进客户）
- 工作满意度：从"打杂"到"专注核心"

### 旅程 3：老板 - 张总

**角色背景：** 张总是这家公司的创始人，公司有80多人，业务涉及多个领域。他最头疼的是：**不知道下面的人在干什么，经营数据靠月底报表，总是滞后。**

#### 开场：信息黑洞

周一例会，张总问："上周销售情况怎么样？"

销售总监："挺好的，有几个单子在谈。"

张总追问："具体数据呢？"

销售总监："我让小王整理一下，下午发给您。"

张总心里叹气——**每次都是"下午发给您"，为什么不能现在就知道？**

#### 上升行动：透明化变革

公司上线了AI-Automated-office，张总第一时间安装了**数据看板插件**。

他打开看板，眼前一亮：

- **销售数据**：本月成交额、订单数、转化率
- **财务数据**：应收款、应付款、现金流
- **生产数据**：产能利用率、生产进度
- **售后数据**：工单数、处理时长、客户满意度
- **任务追踪**：每个部门的关键任务状态

**最让他惊喜的是：** 他可以看到每个任务卡在哪里——
- "采购部：原材料采购单" → 状态：等待审批（卡了3天）
- "销售部：XX客户报价" → 状态：等待客户确认

#### 高潮：决策时刻

周五下午，张总看到数据看板上的预警：**应收账款超过90天的有3笔，共计87万。**

他立刻打开系统，找到对应的销售，问："这3笔账款什么情况？需要我介入吗？"

销售回复："张总，其中2笔客户在走付款流程，1笔可能有风险，我正在催。"

张总点点头——**问题在爆发前就被发现了。**

#### 结局：新现实

- 决策速度：从"等月底报表" → "实时数据驱动"
- 风险控制：从"事后发现" → "提前预警"
- 管理效率：从"开会问" → "看板监控"

### 旅程 4：售后工程师 - 老陈

**角色背景：** 老陈是公司的资深售后工程师，干了15年，什么问题都见过。但他最苦恼的是：**每次维修经验都在脑子里，没法传给新人。新员工遇到问题，还是要问他。**

#### 开场：重复劳动

新来的售后小李遇到一个奇怪的设备故障，不知道怎么处理，跑来问老陈。

老陈说："这个问题我去年遇到过，是XX部件的问题，你换个试试。"

小李问："陈哥，这些经验有没有文档啊？"

老陈苦笑："都在我脑子里，没时间整理啊。"

#### 上升行动：知识沉淀

公司上线了AI-Automated-office，老陈安装了**售后工单插件**和**知识库RAG插件**。

他发现：每次完成工单后，系统会提示他：
> "是否将本次维修经验保存到知识库？"

他只需要简单描述一下问题和解决方案，系统会自动生成格式化的知识条目。

**三个月后**，知识库里已经有了200多条维修经验。

#### 高潮：知识复用

新员工小李又遇到一个问题，这次他先问了系统：
> "设备XX故障，显示错误代码E03，怎么处理？"

系统回复：
> "根据知识库，该故障通常由XX部件松动导致，建议检查步骤：1. 打开侧盖 2. 检查XX连接线..."

小李照着步骤，**10分钟解决了问题**，没有打扰老陈。

老陈看到后笑了："这系统，比我讲得还清楚。"

#### 结局：新现实

- 知识传承：从"靠人" → "靠系统"
- 新人上手时间：从3个月 → 1个月
- 老陈的工作：从"被问烦" → "专注疑难问题"

### 旅程 5：招标专员 - 小刘

**角色背景：** 小刘负责公司的招投标工作，每次做标书都是一场"时间战"——找模板、改格式、核对资质、调整报价...一份标书往往要花3天以上。

#### 开场：通宵赶标书

周四下午，公司决定参与一个紧急招标，周五下午截止。

小刘看着厚厚的招标文件，心里发慌：**又要通宵了。**

她开始手动整理：公司资质、业绩证明、技术方案、报价表...每一样都要仔细核对，生怕出错。

#### 上升行动：AI助攻

公司上线了AI-Automated-office，小刘安装了**标书制定插件**。

她发现系统里已经有：
- 公司资质库（自动更新到期时间）
- 业绩案例库（可按项目类型筛选）
- 标书模板库（多种行业标准模板）

## Innovation & Novel Patterns

### 创新类型：架构创新 + AI深度融合

本产品不是"技术突破型创新"，而是**架构创新 + AI深度融合**：

| 创新维度 | 说明 |
|---------|------|
| **部门化架构** | 从"插件"到"部门"，符合企业组织架构认知 |
| **跨部门数据联动** | 打破数据孤岛，统一数据中台 |
| **部门权限模型** | 权限 = 基础权限 + 部门权限 + 审批权限 |
| **AI深度赋能** | 每个部门配备专属AI助手，而非局部增强 |
| **AI生成流程** | 审批流程可通过对话生成，自动创建数据表 |

### 核心护城河

**护城河不是技术，而是"部门化整合 + 服务深度"：**

| 护城河维度 | 钉钉/飞书 | 本产品 |
|-----------|----------|---------|
| 产品本质 | 工具集合 | **AI赋能ERP** |
| 部门关系 | 各部门独立使用 | **跨部门数据联动** |
| AI定位 | 局部功能增强 | **全流程AI赋能** |
| 数据流 | 数据孤岛 | **统一数据中台** |
| 权限模型 | 应用级权限 | **部门级权限模型** |
| 定制化 | 有限配置 | **部门按需开通** |
| 服务深度 | 标准化SaaS | **软件+垂直服务** |

**核心差异化：**
- 钉钉/飞书：给企业一堆工具，企业自己拼凑流程
- 本产品：给企业一个AI赋能的ERP，看企业有哪些部门，就提供哪些部门的AI能力

### 定制化优势

**按部门定制，而非按功能定制：**
- 传统ERP：按功能模块收费，企业买一堆用不上的功能
- 本产品：**看企业有哪些部门，开通对应部门模块即可**

**定制化流程：**
1. 了解企业组织架构（有哪些部门）
2. 开通对应的核心部门模块
3. 按需安装扩展部门模块
4. AI辅助配置审批流程
5. 跨部门数据自动联动

### 验证方法

| 验证点 | 方法 |
|-------|------|
| 部门化架构是否接受 | MVP阶段验证企业对"部门模块"的认知是否自然 |
| 跨部门联动价值 | 验证销售→财务→仓储的数据联动是否产生效率提升 |
| AI生成流程可用性 | 验证用户是否愿意通过对话创建审批流程 |
| 客户粘性 | 客户续费率、部门扩展率、服务深度 |

### 风险与应对

| 风险 | 应对策略 |
|-----|---------|
| **大厂复制** | 部门化架构需要深度理解企业流程，大厂难以快速跟进 |
| **技术同质化** | 用服务深度和部门联动绑定客户 |
| **客户流失** | 深度服务绑定，跨部门数据联动形成切换成本 |
| **服务规模化难** | 部门模块化降低边际成本，标准服务+定制配置 |

#### AI纠偏反馈学习机制

> **核心理念：** 用户手动修改AI结果时，通过对话告诉AI"为什么改"，AI将纠正记录到"错题集"，实现越用越智能。

### AI Agent通信机制（平台内置基础功能）

> **说明：** AI Agent通信机制确保不同员工的AI助手之间可以安全、透明地交换信息，同时保护员工的数据主权和知情权。

#### 设计原则

| 原则 | 说明 |
|-----|------|
| **透明性** | 员工可查看自己Agent的所有通信记录 |
| **隔离保护** | Agent不能擅自干预其他员工的工作 |
| **确认机制** | 重要消息需员工确认后才发送 |
| **标识机制** | Agent发送的消息必须带"AI助手"标识 |
| **撤回机制** | 员工可撤回Agent发送的消息 |

#### 通信架构

```
┌─────────────────────────────────────────────────────────────────┐
│                    AI Agent通信流程                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  员工A                                              员工B       │
│  ┌─────────┐                                    ┌─────────┐    │
│  │ 员工A   │◄──── 确认发送 ────────────────────►│ 员工B   │    │
│  │         │                                    │         │    │
│  └────┬────┘                                    └────┬────┘    │
│       │                                               │         │
│       ▼                                               ▼         │
│  ┌─────────┐         Agent消息代理            ┌─────────┐    │
│  │ AI Agent│─────────────────────────────────►│ AI Agent│    │
│  │   A     │     (带"AI助手"标识)              │   B     │    │
│  └────┬────┘                                    └────┬────┘    │
│       │                                               │         │
│       ▼                                               ▼         │
│  ┌──────────────┐                         ┌──────────────┐    │
│  │ 发送记录日志 │                         │ 接收记录日志 │    │
│  │ (员工可见)   │                         │ (员工可见)   │    │
│  └──────────────┘                         └──────────────┘    │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

#### 规则自动应用

- FR318: AI在处理类似场景时自动检索相关纠偏规则
- FR319: 纠偏规则自动注入到AI的System Prompt中

- FR321: AI可以学习纠偏规则，避免重复犯错

#### 错题集管理

- FR322: 用户可以查看、编辑、删除自己的纠偏规则
- FR323: 用户可以按场景筛选和搜索纠偏规则
- FR324: 用户可以测试纠偏规则的效果
- FR325: 系统可以检测并提示冲突的纠偏规则
