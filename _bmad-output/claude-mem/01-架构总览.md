# Claude-Mem 架构总览

## 项目概述

**Claude-Mem** 是一个为 Claude Code 构建的持久化记忆压缩系统，能够跨会话保存上下文。它通过自动捕获工具使用观察、生成语义摘要，并在未来会话中使其可用，使 Claude 能够在会话结束或重新连接后保持知识的连续性。

- **版本**: 9.0.17
- **许可证**: AGPL-3.0
- **运行时**: Node.js 18+ / Bun 1.0+
- **数据库**: SQLite 3 (bun:sqlite)
- **向量存储**: ChromaDB (可选)

---

## 核心设计理念

### 上下文工程原则

Claude-Mem 遵循 **上下文工程** 的核心原则：

> **找到最小的高信号令牌集，最大化期望结果的可能性。**

关键洞察：
- LLM 有一个"注意力预算"，随着上下文增长而耗尽
- 每个令牌都会与其他所有令牌建立注意力关系（n²复杂度）
- 随着上下文长度增加，模型准确性下降
- 上下文必须被视为具有边际收益递减的有限资源

### 记忆压缩策略

采用 **渐进式披露** 策略：
1. **索引层** - 紧凑的搜索结果索引（~50-100 tokens/结果）
2. **时间线层** - 围绕感兴趣结果的时序上下文
3. **详情层** - 仅获取过滤后ID的完整详情（~500-1000 tokens/结果）

**效果**: 约10倍的令牌节省

## 核心组件

### 1. 生命周期钩子系统 (5个钩子)

| 钩子 | 触发时机 | 功能 |
|------|----------|------|
| **SessionStart** | 会话启动时 | 启动Worker服务，注入历史上下文 |
| **UserPromptSubmit** | 用户提交提示时 | 创建会话记录，保存原始提示 |
| **PostToolUse** | 工具执行后 | 捕获工具执行，发送给Worker处理 |
| **Stop** | Claude停止时 | 生成会话摘要 |
| **SessionEnd** | 会话结束时 | 标记会话完成状态 |

**额外组件**: smart-install.js - 缓存依赖检查器（预钩子脚本）

### 2. Worker服务

Express.js HTTP服务器，监听端口37777：

**核心职责**:
- 异步观察处理（通过Claude Agent SDK）
- HTTP API端点（搜索、数据、设置等）
- 实时更新（Server-Sent Events）
- 进程管理（Bun托管）

**主要模块**:
- `DatabaseManager` - 数据库连接管理
- `SessionManager` - 会话状态管理
- `SDKAgent` - AI处理代理
- `SearchManager` - 搜索服务
- `SSEBroadcaster` - 实时推送

### 3. 数据库层

**SQLite + FTS5**:
- `sdk_sessions` - 会话跟踪
- `observations` - 工具执行观察
- `session_summaries` - AI生成的会话摘要
- `user_prompts` - 用户提示存储
- FTS5虚拟表 - 全文搜索

**ChromaDB (可选)**:
- 向量嵌入存储
- 语义搜索支持
- 通过MCP协议集成

### 4. MCP搜索工具

提供4个MCP工具，遵循3层工作流模式：

| 工具 | 功能 | 令牌消耗 |
|------|------|----------|
| `search` | 搜索记忆索引 | ~50-100 tokens/结果 |
| `timeline` | 获取时序上下文 | 中等 |
| `get_observations` | 获取完整详情 | ~500-1000 tokens/结果 |
| `__IMPORTANT` | 工作流文档 | 始终可见 |

### 5. 上下文生成器

**模块化架构**:
- `ContextBuilder.ts` - 主编排器
- `ContextConfigLoader.ts` - 配置加载
- `TokenCalculator.ts` - 令牌经济学计算
- `ObservationCompiler.ts` - 数据检索
- `formatters/` - 输出格式化
- `sections/` - 章节渲染

## 数据流

### 记忆管道

```
Hook (stdin) → Database → Worker Service → SDK Processor → Database → Next Session Hook
```

1. **输入**: Claude Code通过stdin发送工具执行数据到钩子
2. **存储**: 钩子将观察写入SQLite数据库
3. **处理**: Worker服务读取观察，通过SDK处理
4. **输出**: 处理后的摘要写回数据库
5. **检索**: 下一个会话的上下文钩子从数据库读取摘要

### 搜索管道

```
User Query → MCP Tools → HTTP API → SessionSearch → FTS5 → Results → Claude
```

1. **用户查询**: 用户自然语言提问
2. **MCP工具调用**: Claude识别意图并调用MCP搜索工具
3. **HTTP API**: MCP工具调用HTTP端点
4. **SessionSearch**: Worker服务查询FTS5虚拟表
5. **格式化**: 结果格式化后通过MCP返回
6. **展示**: Claude向用户展示格式化结果

## 扩展性设计

### 开源核心 vs Pro功能

**开源核心**:
- 所有Worker API端点完全开放
- Pro功能是无头的（无专有UI元素）
- Pro集成点最小化

**Pro功能（外部）**:
- 增强UI连接相同的localhost端点
- 高级过滤、时间线擦洗、搜索工具
- 许可证验证控制访问

这种架构确保Pro功能扩展而非替换核心功能。
