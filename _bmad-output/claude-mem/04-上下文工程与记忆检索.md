# 上下文工程与记忆检索

## 核心原则

### 上下文工程定义

> **找到最小的高信号令牌集，最大化期望结果的可能性。**

**与提示工程的区别**:
- **提示工程**: 编写和组织LLM指令（一次性任务）
- **上下文工程**: 在推理过程中策划和维护最优令牌集（迭代过程）

### 上下文工程管理的内容

- 系统指令
- 工具定义
- 模型上下文协议(MCP)
- 外部数据
- 消息历史
- 运行时数据检索

---

## 问题：上下文腐烂

### 关键洞察

LLM有一个"注意力预算"，随着上下文增长而耗尽：

- 每个令牌都会与其他所有令牌建立注意力关系（n²复杂度）
- 随着上下文长度增加，模型准确性下降
- 模型对较长序列的训练经验较少
- 上下文必须被视为具有边际收益递减的有限资源

### 解决方案

Claude-Mem 采用 **渐进式披露** 策略，分层检索记忆：

```
索引层 → 时间线层 → 详情层
(紧凑)   (上下文)   (完整)
```

---

## 渐进式披露架构

### 三层工作流

| 层级 | 操作 | 令牌消耗 | 用途 |
|------|------|----------|------|
| **索引层** | `search` | ~50-100 tokens/结果 | 获取紧凑索引 |
| **时间线层** | `timeline` | 中等 | 获取时序上下文 |
| **详情层** | `get_observations` | ~500-1000 tokens/结果 | 获取完整详情 |

### 工作流程

```
1. search(query="authentication bug", limit=10)
         ↓
2. 审查索引，识别相关ID (如 #123, #456)
         ↓
3. get_observations(ids=[123, 456])
         ↓
4. 获取完整详情进行处理
```

**效果**: 约10倍的令牌节省

## 上下文生成流程

### 主入口函数

```typescript
export async function generateContext(
  input?: ContextInput,
  useColors: boolean = false
): Promise<string> {
  // 1. 加载配置
  const config = loadContextConfig();
  
  // 2. 获取项目名称
  const cwd = input?.cwd ?? process.cwd();
  const project = getProjectName(cwd);
  const projects = input?.projects || [project];
  
  // 3. 初始化数据库
  const db = initializeDatabase();
  
  // 4. 查询数据
  const observations = queryObservationsMulti(db, projects, config);
  const summaries = querySummariesMulti(db, projects, config);
  
  // 5. 处理空状态
  if (observations.length === 0 && summaries.length === 0) {
    return renderEmptyState(project, useColors);
  }
  
  // 6. 构建输出
  return buildContextOutput(
    project, observations, summaries, config, cwd, 
    input?.session_id, useColors
  );
}
```

### 构建输出流程

```typescript
function buildContextOutput(
  project: string,
  observations: Observation[],
  summaries: SessionSummary[],
  config: ContextConfig,
  cwd: string,
  sessionId: string | undefined,
  useColors: boolean
): string {
  // 1. 计算令牌经济学
  const economics = calculateTokenEconomics(observations);
  
  // 2. 渲染头部
  output.push(...renderHeader(project, economics, config, useColors));
  
  // 3. 准备时间线数据
  const summariesForTimeline = prepareSummariesForTimeline(displaySummaries, summaries);
  const timeline = buildTimeline(observations, summariesForTimeline);
  const fullObservationIds = getFullObservationIds(observations, config.fullObservationCount);
  
  // 4. 渲染时间线
  output.push(...renderTimeline(timeline, fullObservationIds, config, cwd, useColors));
  
  // 5. 渲染最近摘要
  if (shouldShowSummary(config, mostRecentSummary, mostRecentObservation)) {
    output.push(...renderSummaryFields(mostRecentSummary, useColors));
  }
  
  // 6. 渲染先前消息
  const priorMessages = getPriorSessionMessages(observations, config, sessionId, cwd);
  output.push(...renderPreviouslySection(priorMessages, useColors));
  
  // 7. 渲染页脚
  output.push(...renderFooter(economics, config, useColors));
  
  return output.join('\n').trimEnd();
}
```

## 令牌经济学

### 计算函数

```typescript
export interface TokenEconomics {
  totalObservations: number;
  totalReadTokens: number;
  totalDiscoveryTokens: number;
  savings: number;
  savingsPercent: number;
}

export function calculateTokenEconomics(
  observations: Observation[]
): TokenEconomics {
  const totalObservations = observations.length;
  const totalReadTokens = observations.reduce(
    (sum, obs) => sum + (obs.discovery_tokens || 0), 
    0
  );
  const totalDiscoveryTokens = observations.reduce(
    (sum, obs) => sum + estimateTokens(obs), 
    0
  );
  
  const savings = totalDiscoveryTokens - totalReadTokens;
  const savingsPercent = totalDiscoveryTokens > 0 
    ? (savings / totalDiscoveryTokens) * 100 
    : 0;
  
  return {
    totalObservations,
    totalReadTokens,
    totalDiscoveryTokens,
    savings,
    savingsPercent
  };
}
```

### 令牌估算

```typescript
export const CHARS_PER_TOKEN_ESTIMATE = 4;

export function calculateObservationTokens(observation: Observation): number {
  const fields = [
    observation.title,
    observation.subtitle,
    observation.narrative,
    observation.facts,
    observation.concepts
  ];
  
  const totalChars = fields
    .filter(Boolean)
    .join(' ')
    .length;
  
  return Math.ceil(totalChars / CHARS_PER_TOKEN_ESTIMATE);
}
```

## 上下文注入端点

### 请求格式

```
GET /api/context/inject?projects=main,worktree-branch&colors=true
```

**参数**:
- `projects` - 逗号分隔的项目列表（支持worktree）
- `colors` - 是否使用ANSI颜色输出

### 响应格式

```
Content-Type: text/plain; charset=utf-8

[上下文文本]
```

### 处理流程

```typescript
private handleContextInject = async (req: Request, res: Response) => {
  // 1. 解析项目参数
  const projectsParam = req.query.projects || req.query.project;
  const useColors = req.query.colors === 'true';
  const projects = projectsParam.split(',').map(p => p.trim()).filter(Boolean);
  
  // 2. 导入上下文生成器
  const { generateContext } = await import('../../../context-generator.js');
  
  // 3. 生成上下文
  const contextText = await generateContext(
    {
      session_id: 'context-inject-' + Date.now(),
      cwd: `/context/${primaryProject}`,
      projects: projects
    },
    useColors
  );
  
  // 4. 返回纯文本
  res.setHeader('Content-Type', 'text/plain; charset=utf-8');
  res.send(contextText);
};
```

### 统一时间线

多项目查询会生成统一的时间线，按时间戳排序：

```typescript
export function buildTimeline(
  observations: Observation[],
  summaries: SummaryTimelineItem[]
): TimelineItem[] {
  const items: TimelineItem[] = [
    ...observations.map(o => ({ type: 'observation' as const, data: o })),
    ...summaries.map(s => ({ type: 'summary' as const, data: s }))
  ];
  
  return items.sort((a, b) => 
    b.data.created_at_epoch - a.data.created_at_epoch
  );
}
```

## 最佳实践

### 上下文检索策略

| 场景 | 推荐策略 |
|------|----------|
| 静态内容 | 预推理检索或混合 |
| 需要动态探索 | 即时上下文 |
| 扩展来回对话 | 压缩 |
| 迭代开发 | 结构化笔记记录 |
| 复杂研究 | 子代理架构 |
| 快速模型改进 | "做最简单有效的事" |

### 关键要点

1. **上下文是有限的**: 视为具有注意力预算的珍贵资源
2. **整体思考**: 考虑LLM可用的整个状态
3. **保持最小**: 更多上下文不总是更好
4. **迭代进行**: 每次传递给模型时进行上下文策划
5. **为自主性设计**: 随着模型改进，让它们智能行动
6. **从简单开始**: 用最小设置测试，基于失败模式添加

### 反模式

- ❌ 把所有东西塞进提示
- ❌ 创建脆弱的if-else逻辑
- ❌ 构建臃肿的工具集
- ❌ 塞入详尽的边缘情况作为示例
- ❌ 假设更大的上下文窗口解决一切
- ❌ 忽略长时间交互中的上下文污染
