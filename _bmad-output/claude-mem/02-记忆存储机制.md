# 记忆存储机制

## 数据库架构

Claude-Mem 使用 **SQLite 3** 作为主存储引擎，配合 **bun:sqlite** 原生模块实现高性能数据访问。

### 数据库位置

```
~/.claude-mem/claude-mem.db
```

数据库使用 **WAL (Write-Ahead Logging)** 模式支持并发读写。

---

## 核心数据表

### 1. sdk_sessions - 会话跟踪表

存储活跃和已完成的会话信息。

```sql
CREATE TABLE sdk_sessions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  content_session_id TEXT UNIQUE NOT NULL,    -- Claude Code会话ID
  memory_session_id TEXT UNIQUE,               -- SDK记忆会话ID
  project TEXT NOT NULL,                       -- 项目名称
  user_prompt TEXT,                            -- 用户提示
  started_at TEXT NOT NULL,                    -- 开始时间(ISO)
  started_at_epoch INTEGER NOT NULL,           -- 开始时间戳
  completed_at TEXT,                           -- 完成时间(ISO)
  completed_at_epoch INTEGER,                  -- 完成时间戳
  status TEXT CHECK(status IN ('active', 'completed', 'failed')) 
    NOT NULL DEFAULT 'active',                 -- 会话状态
  worker_port INTEGER,                         -- Worker端口
  prompt_counter INTEGER DEFAULT 0             -- 提示计数器
);

-- 索引
CREATE INDEX idx_sdk_sessions_claude_id ON sdk_sessions(content_session_id);
CREATE INDEX idx_sdk_sessions_sdk_id ON sdk_sessions(memory_session_id);
CREATE INDEX idx_sdk_sessions_project ON sdk_sessions(project);
CREATE INDEX idx_sdk_sessions_status ON sdk_sessions(status);
CREATE INDEX idx_sdk_sessions_started ON sdk_sessions(started_at_epoch DESC);
```

**字段说明**:
- `content_session_id`: Claude Code的内容会话标识
- `memory_session_id`: SDK生成的记忆会话标识（用于恢复）
- `project`: 项目名称（从工作目录提取）
- `prompt_counter`: 多提示会话中的提示序号

### 2. observations - 观察记录表

存储工具执行的观察数据，采用分层结构。

```sql
CREATE TABLE observations (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  memory_session_id TEXT NOT NULL,             -- 关联的SDK会话
  project TEXT NOT NULL,                       -- 项目名称
  type TEXT NOT NULL CHECK(type IN (
    'decision', 'bugfix', 'feature', 
    'refactor', 'discovery', 'change'
  )),                                          -- 观察类型
  text TEXT,                                   -- 原始文本
  title TEXT,                                  -- 标题
  subtitle TEXT,                               -- 副标题
  narrative TEXT,                              -- 叙述性描述
  facts TEXT,                                  -- 事实列表(JSON)
  concepts TEXT,                               -- 概念标签(JSON)
  files_read TEXT,                             -- 读取的文件(JSON)
  files_modified TEXT,                         -- 修改的文件(JSON)
  prompt_number INTEGER,                       -- 提示序号
  discovery_tokens INTEGER DEFAULT 0,          -- 发现令牌数
  created_at TEXT NOT NULL,                    -- 创建时间(ISO)
  created_at_epoch INTEGER NOT NULL,           -- 创建时间戳
  
  FOREIGN KEY(memory_session_id) 
    REFERENCES sdk_sessions(memory_session_id) 
    ON DELETE CASCADE
);

-- 索引
CREATE INDEX idx_observations_session ON observations(memory_session_id);
CREATE INDEX idx_observations_project ON observations(project);
CREATE INDEX idx_observations_type ON observations(type);
CREATE INDEX idx_observations_created ON observations(created_at_epoch DESC);
```

**观察类型**:
| 类型 | 说明 |
|------|------|
| `decision` | 架构或设计决策 |
| `bugfix` | Bug修复和纠正 |
| `feature` | 新功能或能力 |
| `refactor` | 代码重构和清理 |
| `discovery` | 关于代码库的学习 |
| `change` | 通用变更和修改 |

### 自动同步触发器

FTS5表通过触发器与主表保持同步：

```sql
-- 插入触发器
CREATE TRIGGER observations_ai AFTER INSERT ON observations BEGIN
  INSERT INTO observations_fts(rowid, title, subtitle, narrative, text, facts, concepts)
  VALUES (new.id, new.title, new.subtitle, new.narrative, new.text, new.facts, new.concepts);
END;

-- 更新触发器
CREATE TRIGGER observations_au AFTER UPDATE ON observations BEGIN
  INSERT INTO observations_fts(observations_fts, rowid, title, subtitle, narrative, text, facts, concepts)
  VALUES('delete', old.id, old.title, old.subtitle, old.narrative, old.text, old.facts, old.concepts);
  INSERT INTO observations_fts(rowid, title, subtitle, narrative, text, facts, concepts)
  VALUES (new.id, new.title, new.subtitle, new.narrative, new.text, new.facts, new.concepts);
END;

-- 删除触发器
CREATE TRIGGER observations_ad AFTER DELETE ON observations BEGIN
  INSERT INTO observations_fts(observations_fts, rowid, title, subtitle, narrative, text, facts, concepts)
  VALUES('delete', old.id, old.title, old.subtitle, old.narrative, old.text, old.facts, old.concepts);
END;
```

## 数据访问层

### ClaudeMemDatabase

新的数据库入口点，替代SessionStore：

```typescript
export class ClaudeMemDatabase {
  public db: Database;

  constructor(dbPath: string = DB_PATH) {
    // 确保数据目录存在
    ensureDir(DATA_DIR);
    
    // 创建数据库连接
    this.db = new Database(dbPath, { create: true, readwrite: true });
    
    // 应用优化设置
    this.db.run('PRAGMA journal_mode = WAL');
    this.db.run('PRAGMA synchronous = NORMAL');
    this.db.run('PRAGMA foreign_keys = ON');
    this.db.run('PRAGMA temp_store = memory');
    this.db.run(`PRAGMA mmap_size = ${256 * 1024 * 1024}`);  // 256MB
    this.db.run(`PRAGMA cache_size = 10000`);
    
    // 运行所有迁移
    const migrationRunner = new MigrationRunner(this.db);
    migrationRunner.runAllMigrations();
  }
}
```

### SQLite优化配置

| 配置 | 值 | 说明 |
|------|-----|------|
| `journal_mode` | WAL | 写前日志，支持并发 |
| `synchronous` | NORMAL | 平衡性能和安全 |
| `foreign_keys` | ON | 启用外键约束 |
| `temp_store` | memory | 临时表存内存 |
| `mmap_size` | 256MB | 内存映射大小 |
| `cache_size` | 10000页 | 缓存页数 |

## 观察存储函数

```typescript
export function storeObservation(
  db: Database,
  memorySessionId: string,
  project: string,
  observation: ObservationInput,
  promptNumber?: number,
  discoveryTokens: number = 0,
  overrideTimestampEpoch?: number
): StoreObservationResult {
  const timestampEpoch = overrideTimestampEpoch ?? Date.now();
  const timestampIso = new Date(timestampEpoch).toISOString();

  const stmt = db.prepare(`
    INSERT INTO observations
    (memory_session_id, project, type, title, subtitle, facts, narrative, concepts,
     files_read, files_modified, prompt_number, discovery_tokens, created_at, created_at_epoch)
    VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?)
  `);

  const result = stmt.run(
    memorySessionId,
    project,
    observation.type,
    observation.title,
    observation.subtitle,
    JSON.stringify(observation.facts),
    observation.narrative,
    JSON.stringify(observation.concepts),
    JSON.stringify(observation.files_read),
    JSON.stringify(observation.files_modified),
    promptNumber || null,
    discoveryTokens,
    timestampIso,
    timestampEpoch
  );

  return {
    id: Number(result.lastInsertRowid),
    createdAtEpoch: timestampEpoch
  };
}
```

## 性能考虑

### 索引策略

- 所有外键列都有索引
- 时间戳列使用DESC索引
- 项目+时间戳组合索引
- 类型列索引

### 查询优化

- FTS5全文搜索比LIKE查询快得多
- 触发器同步开销最小
- bun:sqlite连接复用高效
- 同步API性能更好

### 安全措施

- 所有FTS5查询正确转义
- 双引号转义: `query.replace(/"/g, '""')`
- 全面的SQL注入测试套件
