# brain-mcp-cli 架构设计分析

## 整体架构模式

brain-mcp-cli 采用**分层模块化架构**，结合**插件注册机制**，实现了高度可扩展的对话记忆系统。

### 架构层次图

```
                         │ MCP Protocol (stdio)
```

## 核心设计模式

### 1. 插件注册模式（Plugin Registry Pattern）

**位置**：`brain_mcp/ingest/registry.py`

**实现原理**：
```python
# 全局注册表
_REGISTRY: dict[str, BaseIngester] = {}

# 装饰器注册
def register(cls):
    instance = cls()
    _REGISTRY[instance.source_type] = instance
    return cls

# 使用方式
@register
class ClaudeCodeIngester(BaseIngester):
    source_type = "claude-code"
    ...
```

**优势**：
- 解耦摄入器实现与核心系统
- 支持动态添加新的数据源
- 统一的发现和调用接口

**扩展点**：
```python
# 添加新数据源只需：
# 1. 继承 BaseIngester
# 2. 使用 @register 装饰器
# 3. 实现必需方法

@register
class MyCustomIngester(BaseIngester):
    @property
    def source_type(self) -> str:
        return "my-source"
    
    @property
    def display_name(self) -> str:
        return "My Custom Source"
    
    def discover(self) -> list[dict]:
        # 发现数据源逻辑
        ...
    
    def ingest(self, source_path: str) -> list[dict]:
        # 摄入逻辑
        ...
```

### 2. 抽象基类模式（Abstract Base Class Pattern）

**位置**：`brain_mcp/ingest/base.py`, `brain_mcp/embed/provider.py`

**摄入器基类设计**：
```python
class BaseIngester(ABC):
    @property
    @abstractmethod
    def source_type(self) -> str:
        """唯一标识符"""
        ...
    
    @property
    @abstractmethod
    def display_name(self) -> str:
        """人类可读名称"""
        ...
    
    @abstractmethod
    def discover(self) -> list[dict]:
        """发现数据源"""
        ...
    
    @abstractmethod
    def ingest(self, source_path: str) -> list[dict]:
        """摄入数据"""
        ...
    
    def incremental_ingest(self, source_path: str, state: dict):
        """增量摄入（可选实现）"""
        # 默认实现：全量重新摄入
        records = self.ingest(source_path)
        return records, {"last_full_ingest": datetime.now().isoformat()}
```

**嵌入提供者基类设计**：
```python
class EmbeddingProvider(ABC):
    @abstractmethod
    def embed_batch(self, texts: list[str]) -> list[list[float]]:
        """批量嵌入"""
        ...
    
    @abstractmethod
    def embed_query(self, text: str) -> list[float]:
        """查询嵌入"""
        ...
    
    @property
    @abstractmethod
    def dimension(self) -> int:
        """向量维度"""
        ...
    
    @property
    @abstractmethod
    def provider_name(self) -> str:
        """提供者名称"""
        ...
```

**优势**：
- 定义统一接口契约
- 支持多态替换
- 强制子类实现核心方法

### 3. 单例模式（Singleton Pattern）

**位置**：`brain_mcp/server/db.py`

**实现方式**：模块级缓存

```python
# 模块级单例变量
_embedding_model = None
_conversations_db: Optional[duckdb.DuckDBPyConnection] = None
_lance_db = None
_summaries_lance = None

def get_embedding_model():
    """获取缓存的嵌入模型（首次调用时加载）"""
    global _embedding_model
    if _embedding_model is None:
        from brain_mcp.embed.provider import get_provider
        _embedding_model = get_provider()
    return _embedding_model

def get_conversations() -> duckdb.DuckDBPyConnection:
    """获取缓存的DuckDB连接"""
    global _conversations_db
    if _conversations_db is None:
        cfg = get_config()
        _conversations_db = duckdb.connect()
        _conversations_db.execute(f"""
            CREATE VIEW IF NOT EXISTS conversations
            AS SELECT * FROM read_parquet('{cfg.parquet_path}')
        """)
    return _conversations_db
```

**优势**：
- 避免重复加载大型模型
- 连接复用，减少开销
- 延迟初始化（Lazy Loading）

**注意事项**：
- 模块级变量在进程生命周期内有效
- 不适用于多进程环境（每个进程独立实例）

3. **配置验证**：
```python
def validate_config(cfg: BrainConfig) -> list[str]:
    """验证配置并返回警告列表（不抛异常）"""
    warnings = []
    
    if not cfg.data_dir.exists():
        warnings.append(f"Data directory does not exist: {cfg.data_dir}")
```

## 关键技术决策

### 1. 为什么选择 DuckDB？

**优势**：
- 列式存储，适合分析查询
- 无需独立服务器，嵌入式运行
- 支持Parquet格式，与数据湖生态兼容
- SQL接口，学习成本低
- 高性能聚合和分析

**适用场景**：
- 对话元数据查询（按日期、来源、项目过滤）
- 统计分析（消息计数、词频统计）
- 全文搜索（ILIKE模式匹配）

### 2. 为什么选择 LanceDB？

**优势**：
- 无服务器架构，无需独立进程
- 支持向量搜索 + 全文搜索 + 混合搜索
- 自动索引管理
- 与Pandas/PyArrow无缝集成
- 支持增量更新

**适用场景**：
- 语义相似度搜索
- 混合检索（向量 + 关键词）
- 摘要向量存储

### 3. 为什么选择 FastEmbed？

**优势**：
- 轻量级（107MB vs sentence-transformers的1.3GB）
- 基于ONNX，无需PyTorch
- 快速推理
- 足够好的质量

**权衡**：
- 维度较低（384 vs 768），可能损失部分语义信息
- 但实际使用中质量差异不大

### 4. 为什么选择 Parquet 格式？

**优势**：
- 列式存储，压缩率高
- 支持复杂嵌套结构
- 跨平台兼容
- DuckDB原生支持

**数据模式**：

## 扩展性设计

### 1. 添加新数据源

**步骤**：
1. 创建新的摄入器类，继承 `BaseIngester`
2. 使用 `@register` 装饰器注册
3. 实现必需方法
4. 在配置中添加数据源

**示例**：
```python

        # 发现逻辑
        ...
    
    def ingest(self, source_path: str) -> list[dict]:
        # 摄入逻辑

            record = make_record(
                source="my-custom",
```

## 总结

brain-mcp-cli的架构设计体现了以下核心原则：

1. **模块化**：清晰的模块边界，易于理解和维护
2. **可扩展**：插件机制支持添加新数据源和工具
3. **本地优先**：无外部依赖，完全本地运行
4. **渐进增强**：基础功能无需嵌入，高级功能逐步启用
5. **性能优化**：延迟加载、批处理、连接复用
6. **优雅降级**：摘要不可用时回退到原始数据

这些设计决策使其成为一个既强大又灵活的对话记忆系统。
