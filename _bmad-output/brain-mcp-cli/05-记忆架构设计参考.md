# brain-mcp-cli 记忆架构设计参考

## 1. 记忆架构核心理念

### 1.1 从"事实存储"到"认知重建"

brain-mcp-cli的记忆架构与传统记忆工具有本质区别：

| 维度 | 传统记忆工具 | brain-mcp记忆架构 |
|------|-------------|-------------------|
| **存储对象** | 孤立的事实、键值对 | 完整的对话上下文 |
| **检索方式** | 精确匹配、简单关联 | 语义相似度、认知状态重建 |
| **时间维度** | 静态快照 | 时间轨迹、演变追踪 |
| **知识组织** | 扁平化列表 | 领域分层、阶段标记 |
| **价值定位** | 外部数据库 | 认知假肢（Cognitive Prosthetic） |

### 1.2 记忆层次模型

```
┌─────────────────────────────────────────────────────────┐
```

## 3. 记忆检索机制

### 3.1 多维度检索策略

#### 3.1.1 语义检索

**原理**：基于向量相似度找到概念相关的记忆

```python
def semantic_memory_retrieval(query: str, limit: int = 10):
    """语义记忆检索"""
    # 1. 查询向量化
    query_embedding = get_embedding(query)
    
    # 2. 向量相似度搜索
    results = lance_db.search(query_embedding).limit(limit)
    
    # 3. 相似度计算
    for result in results:
        result["similarity"] = 1 / (1 + result["_distance"])
    
    return results
```

**优势**：
- 找到概念相关的记忆，即使没有关键词匹配
- 支持模糊查询、同义词查询
- 跨语言检索（多语言嵌入模型）

#### 3.1.2 关键词检索

**原理**：基于关键词精确匹配

```python
def keyword_memory_retrieval(keyword: str, limit: int = 20):
```

**优势**：

**原理**：融合语义检索和关键词检索

```python
def hybrid_memory_retrieval(query: str, limit: int = 15):
```

#### 3.1.4 过滤检索

**原理**：基于元数据过滤

```python
def filtered_memory_retrieval(
    query: str,
    domain: str = None,
    importance: str = None,
    thinking_stage: str = None,
    date_range: tuple = None,
):
    """过滤记忆检索"""
    filters = []
    
    if domain:
        filters.append(f"domain_primary = '{domain}'")
    if importance:
        filters.append(f"importance = '{importance}'")
    if thinking_stage:
        filters.append(f"thinking_stage = '{thinking_stage}'")
    if date_range:
        start, end = date_range
        filters.append(f"created >= '{start}' AND created < '{end}'")
    
    where_clause = " AND ".join(filters)
    
    results = lance_db.search(query).where(where_clause).limit(20)
    
    return results
```

**优势**：
- 精确控制检索范围
- 支持多维度过滤
- 减少无关结果

### 3.2 认知状态检索

#### 3.2.1 领域状态重建（tunnel_state）

**目标**：重建某个领域的完整认知状态

```python
def tunnel_state(domain: str, limit: int = 10) -> DomainMemory:
    """重建领域认知状态"""
    # 1. 查询领域相关摘要
    rows = db.execute("""
        SELECT summary, thinking_stage, importance, emotional_tone,
               open_questions, decisions, concepts, key_insights,
               cognitive_pattern, problem_solving_approach
        FROM summaries
        WHERE domain_primary = ?
        ORDER BY summarized_at DESC
        LIMIT ?
    """, [domain, limit]).fetchall()
    
    # 2. 聚合信息
    all_questions = []
    all_decisions = []
    all_concepts = set()
    all_insights = []
    importance_counts = {"breakthrough": 0, "significant": 0, "routine": 0}
    stage_counts = {}
    
    for row in rows:
        all_questions.extend(parse_json(row["open_questions"]))
        all_decisions.extend(parse_json(row["decisions"]))
        all_concepts.update(parse_json(row["concepts"]))
        all_insights.extend(parse_json(row["key_insights"]))
        
        imp = row["importance"] or "routine"
        importance_counts[imp] += 1
        
        stage = row["thinking_stage"] or ""
        stage_counts[stage] = stage_counts.get(stage, 0) + 1
    
    # 3. 构建领域记忆
    latest = rows[0]
    
    return DomainMemory(
        domain=domain,
        thinking_stage=latest["thinking_stage"],
        emotional_tone=latest["emotional_tone"],
        open_questions=all_questions[:10],
        decisions=all_decisions[:7],
        concepts=all_concepts,
        key_insights=all_insights[:5],
        conversation_count=len(rows),
        breakthrough_count=importance_counts["breakthrough"],
        significant_count=importance_counts["significant"],
        connected_domains=set(),  # 从connections_to聚合
        last_active=datetime.now(),
        engagement_history=[],
    )
```

#### 3.2.3 上下文切换成本（switching_cost）

**目标**：量化切换领域的认知成本

```python
def switching_cost(current_domain: str, target_domain: str):
    """计算上下文切换成本"""
    # 1. 获取当前领域状态
    current_state = tunnel_state(current_domain)
    
    # 2. 获取目标领域状态
    target_state = tunnel_state(target_domain)
    
    # 3. 计算开放问题成本
    open_questions_cost = len(current_state.open_questions)
    
    # 4. 计算概念重叠
    shared_concepts = current_state.concepts & target_state.concepts
    concept_overlap = len(shared_concepts) / max(len(current_state.concepts), 1)
    
    # 5. 计算重要性成本
    importance_cost = (
        current_state.breakthrough_count * 3 +
        current_state.significant_count * 1
    )
    
    # 6. 综合成本
    total_cost = (
        open_questions_cost * 2 +
        importance_cost * 5 -
        concept_overlap * 10  # 概念重叠降低成本
    )
    
    return {
        "current_domain": current_domain,
        "target_domain": target_domain,
        "total_cost": max(0, total_cost),
        "open_questions_left": current_state.open_questions,
        "shared_concepts": list(shared_concepts),
        "importance_at_stake": {
            "breakthroughs": current_state.breakthrough_count,
            "significant": current_state.significant_count,
        },
    }
```

## 6. 记忆关联机制

### 6.1 概念关联

**提取共享概念**：
```python
def find_related_by_concepts(conversation_id: str, limit: int = 10):
    """基于概念找相关对话"""
    # 1. 获取当前对话的概念
    current = get_summary(conversation_id)
    current_concepts = set(parse_json(current["concepts"]))
    
    # 2. 查询有共享概念的对话
    rows = db.execute("""
        SELECT conversation_id, concepts
        FROM summaries
        WHERE conversation_id != ?
    """, [conversation_id]).fetchall()
    
    # 3. 计算概念重叠度
    related = []
    for row in rows:
        concepts = set(parse_json(row["concepts"]))
        overlap = len(current_concepts & concepts)
        if overlap > 0:
            related.append((row["conversation_id"], overlap))
    
    # 4. 排序返回
    related.sort(key=lambda x: -x[1])
    return related[:limit]
```

### 6.2 领域关联

**跨领域连接**：
```python
def find_connected_domains(domain: str):
    """查找关联领域"""
    # 1. 获取领域的概念集合
    rows = db.execute("""
        SELECT concepts, domain_secondary
        FROM summaries
        WHERE domain_primary = ?
    """, [domain]).fetchall()
    
    # 2. 聚合概念
    all_concepts = set()
    secondary_domains = []
    for row in rows:
        all_concepts.update(parse_json(row["concepts"]))
        if row["domain_secondary"]:
            secondary_domains.append(row["domain_secondary"])
    
    # 3. 查找共享概念的其他领域
    connected = []
    for other_domain in get_all_domains():
        if other_domain == domain:
            continue
        
        other_concepts = get_domain_concepts(other_domain)
        overlap = len(all_concepts & other_concepts)
        
        if overlap > 5:  # 阈值
            connected.append((other_domain, overlap))
    
    # 4. 加上次领域关联
    for sec_domain in secondary_domains:
        if sec_domain not in [c[0] for c in connected]:
            connected.append((sec_domain, 1))
    
    connected.sort(key=lambda x: -x[1])
    return connected
```

### 6.3 时间关联

```python
def find_temporal_related(conversation_id: str, window_days: int = 7):
    """查找时间相近的对话"""
    current = get_conversation(conversation_id)
    current_time = current["created"]
    
    start = current_time - timedelta(days=window_days)
    end = current_time + timedelta(days=window_days)
    
    rows = db.execute("""
        SELECT conversation_id, conversation_title, created
        FROM conversations
        WHERE created >= ? AND created <= ?
          AND conversation_id != ?
        ORDER BY ABS(created - ?)
        LIMIT 10
    """, [start, end, conversation_id, current_time]).fetchall()
    
    return rows
```

## 7. AI-Automated-office项目应用建议

### 7.1 可借鉴的设计理念

#### 7.1.1 认知假肢理念

**核心思想**：记忆系统不仅是存储，更是认知能力的延伸

**应用到AI-Automated-office**：
- 不仅是存储任务和文档，更要追踪工作状态

- 量化上下文切换成本，优化工作流程

#### 7.1.2 渐进式功能层级

**核心思想**：基础功能无需复杂依赖，高级功能逐步启用

**应用到AI-Automated-office**：
```
L1: 基础存储
    - 任务记录
    - 文档存储
    - 简单搜索

L2: 语义理解
    - 任务嵌入
    - 语义搜索
    - 相似任务推荐

L3: 智能分析
    - 任务摘要
    - 进度追踪
```

#### 7.1.3 多维度记忆模型

**核心思想**：从多个维度组织记忆，支持多角度检索

**应用到AI-Automated-office**：
- **时间维度**：任务创建时间、截止时间、完成时间
- **项目维度**：所属项目、相关项目
- **状态维度**：待办、进行中、已完成、阻塞
- **优先级维度**：紧急、重要、常规
- **领域维度**：开发、测试、文档、会议
- **关联维度**：依赖任务、相关文档、相关人员
