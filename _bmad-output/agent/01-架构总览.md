# OpenClaw Agent 架构总览

## 一、架构概述

OpenClaw 是一个功能完备的 AI Agent 系统，采用经典的**四层标准架构**设计，包括感知层、决策层、执行层和记忆层。这些层级共同构成一个闭环智能系统，实现了从消息接收到任务执行的完整流程。

```
┌─────────────────────────────────────────────────────────────────┐
│                      OpenClaw Agent 架构                         │
├─────────────────────────────────────────────────────────────────┤
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐         │
│  │  感知层      │───▶│  决策层      │───▶│  执行层      │         │
│  │ Perception   │    │ Decision    │    │ Execution   │         │
│  └─────────────┘    └─────────────┘    └─────────────┘         │
│         ▲                                      │                │
│         │              ┌─────────────┐         │                │
│         └──────────────│  记忆层      │◀────────┘                │
│                        │  Memory     │                          │
│                        └─────────────┘                          │
└─────────────────────────────────────────────────────────────────┘
```

## 三、四层架构映射

### 3.1 感知层 (Perception Layer)

**核心职责**：接收和处理来自多个通道的输入信息

| 模块 | 路径 | 功能 |
|------|------|------|
| 通道系统 | `src/channels/` | 多通道消息接收与处理 |
| 消息工具 | `src/agents/tools/message-tool.ts` | 消息发送与动作 |
| 图像工具 | `src/agents/tools/image-tool.ts` | 图像理解与分析 |
| Web 工具 | `src/agents/tools/web-*.ts` | 网络搜索与获取 |

**支持的通道**：
- Telegram (`src/telegram/`)
- Discord (`src/discord/`)
- Slack (`src/slack/`)
- Signal (`src/signal/`)
- WhatsApp (`src/whatsapp/`)
- iMessage (`src/imessage/`)
- Web (`src/web/`)
- 更多扩展通道 (`extensions/`)

### 3.2 决策层 (Decision Layer)

**核心职责**：基于上下文和记忆进行推理和规划

| 模块 | 路径 | 功能 |
|------|------|------|
| 系统提示词 | `src/agents/system-prompt.ts` | 构建 Agent 身份和行为约束 |
| 上下文管理 | `src/agents/context.ts` | 模型上下文窗口管理 |
| 模型配置 | `src/agents/models-config.ts` | 模型选择与配置 |
| PI 嵌入运行器 | `src/agents/pi-embedded-runner.ts` | 嵌入式 Agent 运行 |

**决策流程**：
```
用户消息 → 系统提示词注入 → 上下文窗口构建 → 模型推理 → 工具调用决策
```

### 3.3 执行层 (Execution Layer)

**核心职责**：将决策转化为实际操作

| 模块 | 路径 | 功能 |
|------|------|------|
| 工具系统 | `src/agents/tools/` | 工具定义与执行 |
| Bash 工具 | `src/agents/bash-tools.ts` | Shell 命令执行 |
| 沙箱系统 | `src/agents/sandbox.ts` | 安全隔离执行 |
| 子代理注册 | `src/agents/subagent-registry.ts` | 子代理生命周期管理 |

**核心工具集**：
- 文件操作：`read`, `write`, `edit`, `apply_patch`
- 搜索：`grep`, `find`, `ls`
- 执行：`exec`, `process`
- 网络：`web_search`, `web_fetch`
- 通道：`message`, `sessions_send`
- 系统：`gateway`, `cron`, `browser`

### 3.4 记忆层 (Memory Layer)

**核心职责**：存储和检索历史信息与知识

| 模块 | 路径 | 功能 |
|------|------|------|
| 记忆索引管理 | `src/memory/manager.ts` | 向量索引管理 |
| 嵌入模型 | `src/memory/embeddings.ts` | 文本向量化 |
| 混合搜索 | `src/memory/hybrid.ts` | 向量+关键词混合检索 |
| 会话文件 | `src/memory/session-files.ts` | 会话历史存储 |

## 四、关键设计原则

### 4.1 模块化设计

每个层级都有清晰的边界和职责：
- **单向依赖**：感知层 → 决策层 → 执行层
- **双向通信**：所有层级都与记忆层交互
- **松耦合**：通过接口和事件系统解耦

### 4.2 可扩展性

- **通道插件**：通过 `extensions/` 添加新通道
- **工具扩展**：通过插件系统注册新工具
- **模型支持**：支持多家 LLM 提供商

### 4.3 安全性

- **沙箱隔离**：工具执行在 Docker 容器中
- **权限控制**：基于角色的工具访问控制
- **认证管理**：多 Provider 认证轮换
