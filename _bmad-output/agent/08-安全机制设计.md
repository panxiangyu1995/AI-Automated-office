# OpenClaw 安全机制设计

## 一、安全架构概述

OpenClaw 采用多层次纵深防御体系，应对 AI Agent 应用特有的安全威胁，确保系统在开放环境中的鲁棒性和安全性。

## 二、安全威胁模型

### 2.1 Agent 特有威胁

```
┌─────────────────────────────────────────────────────────────────┐
│                    Agent 安全威胁模型                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. Agent Compromise (智能体妥协)                               │
│     攻击者获得 Agent 控制权，保持合法身份                        │
│     难以检测的恶意行为                                          │
│                                                                 │
│  2. Cross-Prompt Injection (XPIA)                               │
│     在外部数据中嵌入恶意指令                                    │
│     使 Agent 执行攻击者命令                                     │
│                                                                 │
│  3. Memory Poisoning (记忆投毒)                                 │
│     注入虚假记忆误导行为                                        │
│     篡改历史上下文                                              │
│                                                                 │
│  4. Tool Abuse (工具滥用)                                       │
│     滥用工具权限                                                │
│     执行未授权操作                                              │
│                                                                 │
│  5. Data Exfiltration (数据泄露)                                │
│     窃取记忆中的敏感信息                                        │
│     通过工具输出泄露数据                                        │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 威胁来源

| 来源 | 描述 | 风险级别 |
|------|------|----------|
| 外部消息 | 用户输入、通道消息 | 高 |
| 文件内容 | 读取的文件可能包含恶意内容 | 中 |
| 网络内容 | 获取的网页、API 响应 | 中 |
| 工具结果 | 其他工具的输出 | 低 |
| 记忆存储 | 被篡改的记忆文件 | 中 |

## 六、执行审批系统

### 6.1 审批流程

```
┌─────────────────────────────────────────────────────────────────┐
│                    执行审批流程                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 命令分析                                                    │
│     ├── 识别命令类型                                            │
│     ├── 检测风险级别                                            │
│     └── 匹配安全策略                                            │
│                                                                 │
│  2. 审批决策                                                    │
│     ├── 自动批准 (安全命令)                                     │
│     ├── 自动拒绝 (黑名单)                                       │
│     └── 请求审批 (敏感操作)                                     │
│                                                                 │
│  3. 用户交互                                                    │
│     ├── 发送审批请求                                            │
│     ├── 显示命令详情                                            │
│     └── 等待用户响应                                            │
│                                                                 │
│  4. 执行处理                                                    │
│     ├── 批准 → 执行命令                                         │
│     ├── 拒绝 → 返回错误                                         │
│     └── 超时 → 自动拒绝                                         │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 6.2 审批配置

```typescript
// src/agents/bash-tools/exec-approval-request.ts
interface ExecApprovalConfig {
  ask: "always" | "sensitive" | "never";
  
  // always: 所有命令都需要审批
  // sensitive: 敏感命令需要审批
  // never: 从不请求审批 (危险)
}

// 敏感命令检测
const SENSITIVE_PATTERNS = [
  /rm\s+-rf/,           // 删除命令
  /sudo/,               // 提权命令
  />\s*\//,             // 写入根目录
  /curl.*\|.*sh/,       // 管道执行
];
```

## 十二、安全最佳实践

### 12.1 部署建议

- 默认启用沙箱
- 配置最小权限
- 定期审计日志
- 及时更新依赖

### 12.2 运维建议

- 监控异常行为
- 定期审查白名单
- 保持认证信息安全
- 制定应急响应计划

### 12.3 开发建议

- 始终验证输入
- 使用安全的默认值
- 记录敏感操作
- 编写安全测试
