# Specification: 部门模块基础框架

## 需求来源

### PRD 需求
- FR20: 用户可以在部门市场浏览和搜索扩展部门模块
- FR21: 管理员可以安装和卸载扩展部门模块
- FR22: 用户可以查看部门模块的评分和评价
- FR23: 管理员可以配置部门模块的访问权限

### 架构约束
- ARCH-01: 分层微内核架构
- ADR-001: 基础架构决策

### UX 规范
- UX-01: VSCode 风格四栏布局
- UX-04: 自然语言交互优先

## 功能规格

### 用户故事

As a 管理员,
I want 管理企业部门模块,
So that 为用户提供差异化的 AI 能力支持。

### 验收场景

#### Scenario 1: 注册部门能力包
- **GIVEN** 系统管理员已登录
- **WHEN** 管理员触发注册部门能力包
- **THEN** 部门能力包被注册到注册表，可以被查询

#### Scenario 2: 加载部门能力包
- **GIVEN** 部门能力包已注册
- **WHEN** 用户访问该部门功能
- **THEN** 部门能力包被加载到运行时

#### Scenario 3: 部门间通信
- **GIVEN** 两个部门都已加载
- **WHEN** 源部门发送消息到目标部门
- **THEN** 目标部门收到消息并处理

## 数据规格

### 输入

| 字段 | 类型 | 必填 | 校验规则 |
|------|------|------|----------|
| id | string (UUID) | 是 | 有效 UUID 格式 |
| code | string | 是 | 小写字母 + 数字，最多 20 字符 |
| name | string | 是 | 2-50 字符 |
| version | string | 是 | SemVer 格式 |
| description | string | 否 | 最多 500 字符 |

### 输出

| 字段 | 类型 | 描述 |
|------|------|------|
| id | string | 部门 ID |
| code | string | 部门代码 |
| name | string | 部门名称 |
| status | string | 状态 |
| capabilities | array | 能力列表 |
| loadedAt | number | 加载时间 |

## 边界条件

- 部门代码冲突：返回 409 Conflict
- 部门不存在：返回 404 Not Found
- 部门依赖未满足：返回 400 Bad Request
- 加载失败：回滚并返回错误

## 错误处理

| 错误码 | 错误信息 | 处理方式 |
|--------|----------|----------|
| DEPT_001 | 部门代码已存在 | 提示用户更换代码 |
| DEPT_002 | 部门不存在 | 返回 404 |
| DEPT_003 | 依赖部门未加载 | 提示先加载依赖 |
| DEPT_004 | 加载失败 | 回滚并记录日志 |
| DEPT_005 | 卸载失败 | 保持原状态并提示 |
