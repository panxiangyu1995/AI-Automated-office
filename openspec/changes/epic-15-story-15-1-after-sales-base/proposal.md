# Epic 15 Story 15.1: After-sales 售后服务模块基础架构

## Why

随着企业业务规模扩大，售后服务成为提升客户满意度和忠诚度的关键环节。当前系统缺少专业的售后工单管理能力，导致：
- 维修进度无法追踪，客户体验差
- 维修经验无法积累，重复问题反复处理
- 服务人员调度效率低，资源浪费

实现售后服务模块可以：
- 规范化售后流程，提升处理效率
- 积累维修经验，形成知识资产
- 为客户提供透明的服务进度追踪
- 降低客服成本，提升NPS

**市场背景：** 售后服务市场规模超千亿，企业对智能售后系统需求迫切。

## What Changes

实现售后服务模块的基础架构，包括：

1. **工单管理核心**
   - 工单类型定义（维修、咨询、投诉）
   - 工单状态机（新建→处理中→待确认→已完成/已取消）
   - 工单优先级（低/中/高/紧急）
   - 工单分配机制

2. **服务人员管理**
   - 服务人员注册和状态管理
   - 专长领域配置
   - 工单负载均衡

3. **前后端实现**
   - Rust后端：`src-tauri/src/service/` 模块
   - React前端：`src/features/service/` 模块
   - 数据库Schema和迁移

4. **系统集成**
   - 与HR模块集成获取员工信息
   - 与Knowledge模块预留集成接口
   - 与消息通知系统集成

## Capabilities

### New Capabilities

- `after-sales-ticket`: 售后工单管理基础能力，支持工单创建、查询、状态流转
- `after-sales-personnel`: 服务人员管理，支持服务人员列表和处理能力配置
- `after-sales-base-ui`: 售后模块前端UI组件和页面

### Modified Capabilities

- 无

## Impact

### 受影响代码

| 路径 | 操作 | 说明 |
|------|------|------|
| `src/features/service/` | 新增 | 售后模块前端 |
| `src-tauri/src/service/` | 新增 | 售后模块后端 |
| `src/components/layout/Sidebar.tsx` | 修改 | 添加动态入口 |
| `src/lib/commandRegistry.ts` | 修改 | 注册命令 |

### 依赖模块

| 模块 | 依赖类型 | 说明 |
|------|----------|------|
| `hr` | 硬依赖 | 获取员工列表用于分配 |
| `knowledge` | 软依赖 | 预留knowledge_id字段 |
| `notification` | 软依赖 | 状态变更通知 |

### 权限模型

```
售后权限 = 人事权限(read) + 售后权限(full) + 审批发起权限
```

| 角色 | 权限 |
|------|------|
| 客服 | 创建工单、查看工单、添加处理记录 |
| 服务人员 | 查看分配工单、更新工单状态 |
| 售后主管 | 所有权限 + 统计查看 |
| 管理员 | 所有权限 |

### 数据库影响

- 新增表：`service_tickets`, `service_personnel`
- 无破坏性变更

### 性能影响

- 工单列表查询：预计 < 100ms（1000条数据）
- 状态更新：预计 < 50ms
