# Proposal: Skill执行引擎

## 问题陈述

当前系统缺少完整的Skill执行引擎实现：

1. **缺少SKILL.md解析器**：无法解析OpenClaw格式的SKILL.md文件
2. **缺少渐进式加载机制**：无法按会话上下文按需加载Skill，控制首轮上下文体积
3. **缺少工具/触发器转换**：无法将Skill中的Tools和Triggers转换为内部格式
4. **缺少执行控制**：无超时控制、重试机制、审计日志
5. **缺少版本管理**：无版本检查、更新、回滚功能
6. **缺少多源加载**：无法从多个来源（Bundled/Managed/Workspace/External）加载Skill

## 影响分析

### 业务影响
- 无法复用OpenClaw生态中的现有Skill
- 无法实现能力扩展的渐进式加载
- 无法保证Skill执行的安全性和可审计性

### 技术影响
- 前端SkillConfiguration.tsx组件无法正常工作
- 工具系统无法与Skill系统集成
- 审计系统缺少Skill执行记录

## 解决方案

### 架构设计

```
┌─────────────────────────────────────────────────────────────┐
│                    Skill System                              │
├─────────────────────────────────────────────────────────────┤
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐       │
│  │  Discovery   │  │   Parsing    │  │   Loading    │       │
│  │  (发现层)    │  │   (解析层)   │  │   (加载层)   │       │
│  └──────────────┘  └──────────────┘  └──────────────┘       │
│         │                 │                 │                │
│         ▼                 ▼                 ▼                │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐       │
│  │  Registry    │  │  Converter   │  │  Executor    │       │
│  │  (注册表)    │  │  (转换器)    │  │  (执行器)    │       │
│  └──────────────┘  └──────────────┘  └──────────────┘       │
│         │                 │                 │                │
│         ▼                 ▼                 ▼                │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐       │
│  │  Version     │  │  Permission  │  │  Audit       │       │
│  │  (版本管理)  │  │  (权限控制)  │  │  (审计日志)  │       │
│  └──────────────┘  └──────────────┘  └──────────────┘       │
└─────────────────────────────────────────────────────────────┘
```

### 核心组件

#### 1. Skill Discovery Layer（发现层）
- 多源加载：Bundled、Managed、Workspace、External
- 优先级合并：后者覆盖前者
- 安全限制：文件大小、数量限制

#### 2. Skill Parsing Layer（解析层）
- SKILL.md解析：Markdown + Frontmatter
- 元数据提取：name、description、version、dependencies
- 工具/触发器识别

#### 3. Skill Loading Layer（加载层）
- 渐进式加载：按需加载，控制提示预算
- 紧凑格式降级：超出预算时使用紧凑格式
- 二分查找最大可容纳前缀

#### 4. Skill Execution Layer（执行层）
- 执行调度：队列管理、并发控制
- 超时控制：可配置超时时间
- 重试机制：指数退避重试
- 审计日志：完整执行记录

### 数据流

```
SKILL.md → Parser → SkillEntry → Registry
                              ↓
                         Converter → InternalTools/Triggers
                              ↓
                         Executor → AuditLog
```

### 技术选型

| 组件 | 技术方案 | 说明 |
|------|----------|------|
| 解析器 | `serde_yaml` + `pulldown-cmark` | YAML Frontmatter + Markdown解析 |
| 注册表 | SQLite + 内存缓存 | 持久化 + 快速访问 |
| 执行器 | Tokio async runtime | 异步执行 |
| 审计 | 复用现有 `audit.rs` | 统一审计链路 |

## 实施计划

### Phase 1: 核心解析

- 实现多源发现

### Phase 3: 执行引擎
- 实现执行器
- 实现超时/重试

### Phase 4: 版本管理
- 实现版本检查
- 实现更新机制
- 实现回滚功能

| 风险 | 影响 | 缓解措施 |
