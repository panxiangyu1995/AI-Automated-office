# Proposal: 心跳机制后端执行引擎

## 问题陈述

当前系统缺少心跳机制的后端实现，无法执行定时检查。前端已有 `HeartbeatChecklist.tsx` 组件，但后端缺少 `heartbeat.rs` 模块来支持：
- 定期Agent回合执行
- HEARTBEAT.md检查清单解析
- 活动时段与时区配置
- 静默处理机制
- 隔离会话模式

## 目标

实现完整的心跳后端执行引擎，使AI助手能够：
1. 定期主动检查系统状态
2. 读取并执行检查清单
3. 在适当时机主动通知用户
4. 实现从"被动响应"到"主动服务"的转变

## 解决方案

### 架构设计

```
┌─────────────────────────────────────────────────────────────┐
│                    Heartbeat Engine                          │
├─────────────────────────────────────────────────────────────┤
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐       │
│  │  Scheduler   │  │  Preflight   │  │  Executor    │       │
│  │  (调度器)    │  │  (预检查)    │  │  (执行器)    │       │
│  └──────────────┘  └──────────────┘  └──────────────┘       │
│         │                 │                 │                │
│         ▼                 ▼                 ▼                │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐       │
│  │  Config      │  │  HEARTBEAT   │  │  Event       │       │
│  │  (配置管理)  │  │  .md Parser  │  │  Emitter     │       │
│  └──────────────┘  └──────────────┘  └──────────────┘       │
└─────────────────────────────────────────────────────────────┘
```

### 核心模块

1. **HeartbeatScheduler** - 心跳调度器
   - 可配置间隔（默认30分钟）
   - 活动时段检查
   - 时区支持

2. **HeartbeatPreflight** - 预检查器
   - 用户状态检查
   - 资源可用性检查
   - 上下文预算检查
   - HEARTBEAT.md门控

3. **HeartbeatExecutor** - 执行器
   - 检查清单执行
   - 隔离会话模式
   - 轻量上下文模式

4. **HeartbeatMdParser** - HEARTBEAT.md解析器
   - Markdown解析
   - 检查项提取
   - 跳过指令识别

5. **HeartbeatEventEmitter** - 事件发射器
   - 状态变更事件
   - 审计日志
   - 通知触发

## 实现路径

### Phase 1: 核心引擎
- 创建 `heartbeat.rs` 模块
- 实现心跳配置结构
- 实现预检查逻辑
- 实现基础执行流程

### Phase 2: HEARTBEAT.md支持
- 实现 Markdown 解析
- 支持检查清单提取
- 支持跳过指令

### Phase 3: 调度与事件
- 集成调度器
- 实现事件发射
- 连接前端事件桥

### Phase 4: 高级特性
- 隔离会话模式
- 轻量上下文模式
- 投递目标配置
- 立即唤醒支持

## 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 性能影响 | 心跳执行可能影响主流程 | 使用独立线程池，预检查跳过无意义心跳 |
| 资源消耗 | 频繁心跳消耗Token | 支持静默模式，空清单跳过 |
| 时区问题 | 跨时区活动时段配置 | 使用UTC存储，本地化显示 |

## 成功指标

1. 心跳按时触发率 > 99%
2. 预检查跳过率合理（避免无意义执行）
3. HEARTBEAT_OK静默处理正确
4. 事件发射完整可审计
5. 前端UI正确显示心跳状态
