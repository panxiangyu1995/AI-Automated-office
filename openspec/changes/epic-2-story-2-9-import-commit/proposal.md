# Proposal: Import Commit and Receipt

## 变更类型
- [x] 新功能
- [ ] 修复
- [ ] 优化
- [ ] 重构

## 背景

Epic 2 用户认证与部门权限系统的导入功能需要支持确认提交。在预览和冲突检测完成后，用户需要确认并提交导入数据。本提案实现导入提交、结果回执和审计日志功能。

### 业务背景
- 管理员需要确认并提交导入数据（FR33）
- 需要防止重复提交
- 需要查看导入结果和失败详情

### 技术背景
- 后端采用 Go 语言（ADR-005）
- 多租户数据库级隔离
- 需要事务处理和幂等性控制

## 目标

实现用户导入的确认提交功能：
1. 预览确认后的提交端点
2. batch_id 幂等性控制
3. 批量写入和结果回执
4. 审计日志记录

## 范围

### 包含
- 提交确认 API
- 幂等性检查和状态管理
- 批量数据写入
- 结果回执生成
- 失败详情导出
- 审计日志写入

### 不包含
- 导入预览功能（E2-S2.9-01）
- 导入 UI 界面（E2-S2.9-03）
- 导出功能（E2-S2.9-03）

## 影响范围

### 后端
- `cloud-server/internal/module/admin/application/service/import_commit_service.go` - 提交服务
- `cloud-server/api/admin/import.go` - API Handler

### 数据库
- 更新 `user_import_batches` 表状态
- 写入 `users` 表
- 写入 `audit_logs` 表

## 风险评估

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|----------|
| 事务超时 | 中 | 高 | 分批提交，设置合理超时 |
| 部分失败数据不一致 | 中 | 高 | 使用数据库事务，失败回滚 |
| 重复提交 | 低 | 高 | 幂等性检查和状态锁定 |

## 实施计划

1. **Step 1**: 设计提交状态机
2. **Step 2**: 实现幂等性检查
3. **Step 3**: 实现批量写入逻辑
4. **Step 4**: 实现结果回执生成
5. **Step 5**: 实现审计日志写入
6. **Step 6**: 创建提交 API
7. **Step 7**: 测试和优化
