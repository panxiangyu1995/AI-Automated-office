## Context

当前AI对话面板需要重构以满足UX设计规范和PRD文档要求。设计参考文件位于 `i:\AI-Automated-office\_bmad-output\UI-PEN\ai-chat-panel-redesign.pen`，该设计文件包含了完整的视觉设计和组件规范。

### 设计参考
- **设计文件**: `ai-chat-panel-redesign.pen`

- 使用项目现有浅色色彩系统
- 符合固定工作台壳层设计（参考VSCode Workbench）
- 支持AI作为一级入口
- 面板宽度固定为420px

## Goals / Non-Goals

**Goals:**
- 重构AI对话面板主框架，优化视觉层次
- 创建可复用的消息气泡组件（用户消息、AI消息）
- 实现工具调用卡片组件，支持状态展示
- 实现反馈消息和建议操作组件
- 统一间距系统和色彩系统
- 确保响应式布局和正确的内容溢出处理

**Non-Goals:**
- 不修改AI对话的后端逻辑
- 不引入新的第三方UI库
- 不改变现有的AI对话数据流

## Decisions

### 1. 组件架构设计
**决策**: 采用原子化设计，将AI对话面板拆分为6个独立组件

**理由**:
- 提高组件复用性
- 便于独立测试和维护
- 支持未来的功能扩展

**组件清单**:
- `AIChatPanel`: 主面板容器
- `MessageBubble`: 消息气泡（用户/AI两种变体）
- `ToolCallCard`: 工具调用状态卡片
- `FeedbackMessage`: 用户反馈消息
- `SuggestionCard`: 建议操作卡片
- `ChatInput`: 输入区域

### 2. 布局系统
**决策**: 使用Flexbox垂直布局，固定面板宽度420px

**理由**:
- 符合UX规范中的固定右侧面板要求
- 消息列表需要垂直滚动
- 输入区域固定在底部

**结构**:
```
AIChatPanel (420px width, flex column)
├── PanelHeader (60px height)
├── FactsSection (auto height, optional)
├── MessageList (flex: 1, scrollable)
│   ├── UserMessage
│   ├── AIMessage
│   ├── ToolCallCard
│   ├── FeedbackMessage
│   └── ...
└── InputArea (auto height)
```

### 3. 色彩系统
**决策**: 使用项目浅色主题，主色调为 `#1E3A5F`

**色彩规范**:
| 用途 | 颜色值 |
|------|--------|
| 品牌主色/用户消息背景 | `#1E3A5F` |
| AI消息背景 | `#F8FAFC` |
| 工具运行中边框 | `#3B82F6` |
| 工具成功边框 | `#22C55E` |
| 反馈消息背景 | `#FFFBEB` |
| 边框色 | `#E2E8F0` |
| 文字主色 | `#1E293B` |
| 文字次要色 | `#64748B` |

### 4. 间距系统
**决策**: 采用8px网格系统

**规范**:
- 消息间距: 24px
- 消息内边距: 14px 18px
- 卡片圆角: 10px
- 气泡圆角: 用户[12,12,0,12], AI[4,16,16,16]
- 组件间隙: 8px-16px

### 5. 消息气泡设计
**决策**: 区分用户消息和AI消息的圆角和颜色

**用户消息**:
- 背景: `#1E3A5F`
- 文字: `#FFFFFF`
- 圆角: `[12,12,0,12]` (右下平直)
- 对齐: 右侧

**AI消息**:
- 背景: `#F8FAFC`
- 文字: `#334155`
- 圆角: `[4,16,16,16]` (左上平直)
- 对齐: 左侧
- 包含头像和名称

### 6. 工具调用卡片状态
**决策**: 使用边框颜色和头部背景区分状态

**运行中状态**:
- 边框: 2px solid `#3B82F6`
- 头部背景: `#EFF6FF`
- 状态标签: "运行中..."

**成功状态**:
- 边框: 2px solid `#22C55E`
- 头部背景: `#F0FDF4`
- 状态标签: "已完成"

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|----------|
| 组件拆分过细导致性能问题 | 使用React.memo优化渲染，避免不必要的重渲染 |
| 固定宽度在不同屏幕尺寸下的适配问题 | 确保面板容器支持响应式，内部组件使用相对单位 |
| 消息列表滚动性能 | 实现虚拟滚动（如消息数量超过100条） |
| 颜色主题切换兼容性 | 使用CSS变量或主题上下文，确保未来支持深色模式 |

## Migration Plan

### 部署步骤
1. 创建新组件文件（保持旧组件可用）
2. 在开发环境测试新组件
3. 逐步替换旧组件引用
4. 移除旧组件代码

### 回滚策略
- 保留旧组件代码直到新组件稳定
- 使用特性开关控制新组件的启用
