## Context

随着对话进行，上下文中累积的消息越来越多，导致：
- LLM API响应变慢（处理更多token）
- Token成本增加
- 本地内存占用增加

**现有代码：**
- `src-tauri/src/agent/context_compression.rs` 存在但未集成
- 消息历史完整保存在SQLite和内存中
- 没有压缩触发机制

**约束：**
- 压缩不能丢失关键信息（人名、日期、金额等）
- 压缩应该是无感的，不影响用户体验
- 需要保留压缩前的完整历史（用于回滚）

## Goals / Non-Goals

**Goals:**
- 实现自动上下文压缩（阈值触发）
- 实现手动上下文压缩（用户触发）
- 生成高质量的对话摘要
- 保留关键实体不被压缩

**Non-Goals:**
- 不改变消息的存储格式（SQLite仍存完整消息）
- 不实现LLM的function calling压缩
- 不支持实时压缩（仅在发送前压缩）

## Decisions

### Decision 1: 压缩触发时机

**选择：** 自动阈值触发 + 手动触发

**自动触发条件：**
```typescript
interface CompressionConfig {
  max_messages: 50,           // 超过50条消息
  max_tokens: 32000,          // 或token数超过32000
  compression_ratio: 0.3,      // 压缩后保留30%
}
```

**手动触发：**
- 用户点击"压缩上下文"按钮
- 快捷键 Ctrl+Shift+C

### Decision 2: 压缩策略

**选择：** 分层压缩 + 摘要生成

**分层策略：**
```
┌─────────────────────────────────────────┐
│ 最近的10轮对话（完整保留）               │
├─────────────────────────────────────────┤
│ 中间的对话（生成摘要，每轮1-2句话）       │
├─────────────────────────────────────────┤
│ 最早的对话（仅保留关键实体）              │
└─────────────────────────────────────────┘
```

**摘要生成提示词：**
```
将以下对话压缩为简洁摘要，保留：
1. 用户的主要意图和问题
2. AI的关键回答和解决方案
3. 重要的事实和数据

格式：[[摘要]]: <压缩内容>
```

### Decision 3: 关键实体保留

**选择：** 实体识别 + 特殊标记

**实体类型：**
- 人名、地名、组织名
- 日期、时间
- 金额、百分比
- 专业术语、缩写

**保留格式：**
```json
{
  "summary": "用户询问项目进度，涉及[人名:张三]和[金额:100万]",
  "entities": [
    {"type": "person", "value": "张三"},
    {"type": "money", "value": "100万"}
  ]
}
```

### Decision 4: 压缩执行位置

**选择：** Rust后端执行压缩

**理由：**
- Token计算在Rust端已有实现
- 减少前端复杂度
- 压缩后的消息格式对前端透明

**流程：**
```
前端发送消息
    ↓
Rust端检查上下文长度
    ↓
超过阈值 → 执行压缩
    ↓
压缩后的上下文发送给LLM
```

## Risks / Trade-offs

| 风险 | 影响 | 缓解措施 |
|-----|------|---------|
| 摘要质量差 | 丢失重要信息 | 保留完整历史，摘要仅用于展示 |
| 压缩触发时机不对 | 关键信息被压缩 | 最近10轮完整保留 |
| Token计算不准确 | 压缩不及时 | 使用多种估算方式交叉验证 |

## Migration Plan

**Phase 1: 完善context_compression.rs**
1. 实现摘要生成逻辑
2. 实现实体识别
3. 实现分层压缩算法

**Phase 2: 集成到消息流程**
1. 在runtime_session.rs中触发压缩
2. 实现压缩状态管理
3. 添加压缩事件emit

**Phase 3: 前端UI**
1. 添加"压缩上下文"按钮
2. 显示压缩状态指示
3. 压缩历史查看

**Phase 4: 调优**
1. 调整压缩阈值
2. 优化摘要质量
3. 性能测试

**Rollback:** 压缩为可选项，可通过配置关闭
