# Proposal: Sub-Agent嵌套调用控制

## 变更类型
- [x] 新功能 (new)

## 背景

在复杂任务处理场景中，主Agent经常需要调用多个Sub-Agent协同工作，而这些Sub-Agent本身可能还需要进一步调用其他Sub-Agent，形成嵌套调用结构。例如：

- 主Agent调用"数据分析Sub-Agent" → 数据分析Sub-Agent调用"报表生成Sub-Agent"
- 主Agent调用"客服Sub-Agent" → 客服Sub-Agent调用"知识库查询Sub-Agent"

为了确保系统的稳定性和可预测性，必须对嵌套调用进行严格控制：

1. **深度限制**：防止无限递归导致的栈溢出和资源耗尽
2. **调用追踪**：记录完整的调用链路，便于调试和审计
3. **循环检测**：防止A→B→A这样的循环调用导致的死循环
4. **超时控制**：确保每个嵌套层级都有超时保护

当前系统缺少嵌套调用控制机制，需要在Story 52.2创建的SubAgentExecutionContext基础上，实现嵌套调用控制逻辑。

## 目标

实现Sub-Agent嵌套调用控制机制，确保嵌套调用安全可控，具体目标包括：

- 实现嵌套调用深度计数器与限制检查，限制最大嵌套深度为3层
- 创建Sub-Agent调用栈追踪，记录完整的调用链路
- 实现调用链路可视化数据生成，支持前端展示
- 添加循环调用检测与防护机制
- 实现嵌套调用超时控制，支持按层级配置超时时间

## 风险评估

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|----------|
| 循环调用导致死循环 | 中 | 高 | 实现严格的循环检测算法，在调用前进行检测 |
| 嵌套深度计算错误 | 中 | 高 | 单元测试覆盖所有深度变化场景 |
| 调用栈内存泄漏 | 低 | 高 | 设置最大调用深度限制，超出后强制清理 |
| 超时时间设置不合理 | 中 | 中 | 提供合理的默认超时值，允许按需配置 |
| 多线程竞态条件 | 低 | 高 | 使用互斥锁保护调用栈的并发访问 |

## 实现步骤

1. **实现嵌套调用深度计数器与限制检查**
   - 在`SubAgentExecutionContext`中集成深度计数器
   - 实现深度递增/递减方法
   - 添加最大深度检查逻辑（最大3层）

2. **创建Sub-Agent调用栈追踪**
   - 定义调用栈数据结构
   - 实现调用栈的push/pop操作
   - 实现调用栈的序列化用于日志记录

3. **实现调用链路可视化数据**
   - 生成前端展示所需的调用链路JSON结构
   - 包含每个调用的层级、时间、状态信息

4. **添加循环调用检测与防护**
   - 实现基于调用链路的循环检测算法
   - 在每次调用前检测是否形成循环
   - 返回明确的循环调用错误

5. **实现嵌套调用超时控制**
   - 实现按层级配置的超时时间
   - 实现超时检测和自动取消机制
   - 清理超时后的调用栈
