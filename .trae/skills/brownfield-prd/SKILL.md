# 棕地项目 PRD 文档生成器

## 概述

本技能用于分析已有代码实现，逆向工程生成系统性的产品需求文档（PRD）。适用于棕地项目（Brownfield Project）的文档化需求，帮助团队理解现有系统的功能实现。

## 核心能力

- **后端 API 分析**：解析 Controller、Service、Mapper 层，提取接口定义、参数、返回值
- **前端页面分析**：分析 Vue/React 组件、路由、状态管理，提取用户交互逻辑
- **数据库模型分析**：解析实体类、表结构、字段约束、关联关系
- **业务流程分析**：串联前后端调用链，绘制完整业务流程图

## 工作流程

### 第一阶段：范围界定

1. **确认分析范围**：询问用户需要分析的功能模块或业务领域
2. **识别入口文件**：找到相关的 Controller、页面组件、数据库表
3. **建立分析边界**：明确哪些文件在分析范围内

### 第二阶段：代码分析

按以下顺序进行分析，逐步深入：

#### 1. 后端 API 分析

```
分析步骤：
1. 定位 Controller 文件，提取所有 API 端点
2. 对每个端点记录：
   - HTTP 方法和路径
   - 请求参数（Query/Path/Body）
   - 返回数据结构
   - 权限要求
3. 追踪 Service 层业务逻辑
4. 检查 Mapper/Repository 层数据操作
```

#### 2. 数据库模型分析

```
分析步骤：
1. 定位实体类（Entity）文件
2. 提取表结构信息：
   - 表名、字段名、数据类型
   - 主键、外键、索引
   - 字段约束（非空、默认值）
3. 分析表间关联关系（一对多、多对多）
4. 查看数据库迁移脚本补充信息
```

#### 3. 前端页面分析

```
分析步骤：
1. 定位页面组件文件
2. 提取页面结构：
   - 页面布局和组件构成
   - 表单字段和验证规则
   - 列表展示字段
3. 分析用户交互：
   - 按钮操作和事件处理
   - 页面跳转逻辑
   - 数据加载方式
4. 追踪 API 调用
```

#### 4. 业务流程串联

```
分析步骤：
1. 从用户操作入口开始
2. 追踪完整的调用链：页面 → API → Service → 数据库
3. 识别分支逻辑和异常处理
4. 记录状态流转
```

## 分析技巧

### 代码追踪策略

1. **自顶向下**：从入口点（Controller/页面）开始，逐层深入
2. **关键词搜索**：使用统一的命名前缀定位相关文件
3. **依赖追踪**：通过 import 语句找到关联模块
4. **注释利用**：充分利用代码注释理解业务逻辑

### 常见模式识别

- **CRUD 模式**：增删改查的标准实现
- **状态机模式**：订单状态、任务状态流转
- **审批流模式**：多级审批、驳回逻辑
- **关联查询模式**：主从表、多表联查

### 文档编写原则

1. **以用户视角描述**：描述"用户能做什么"，而非"代码怎么写"
2. **结构清晰**：使用表格、图表增强可读性
3. **逻辑完整**：覆盖正常流程和异常流程
4. **保持客观**：描述现有实现，不添加主观评价

## 输出规范

### Mermaid 图表使用

- **ER 图**：展示数据库表关系
- **时序图**：展示业务流程调用链
- **流程图**：展示页面跳转和条件分支

### 表格格式

所有列表数据使用 Markdown 表格呈现：
- 列标题明确
- 内容简洁
- 必要时添加说明列

## 注意事项

1. **保护敏感信息**：文档中不要暴露真实的密码、密钥等敏感数据
2. **标注不确定性**：对于推断出的需求，标注"（推断）"
3. **保持更新**：代码变更后及时更新文档
4. **版本管理**：文档中标注生成日期和代码版本
