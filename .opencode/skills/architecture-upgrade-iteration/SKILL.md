# 架构升级迭代优化器

## 核心原则

**在不改变现有功能的前提下，对代码架构进行升级优化。**

优化方向：
- **模块边界优化** - 职责更清晰、耦合更低
- **设计模式应用** - 提升代码可维护性和扩展性
- **代码结构重构** - DRY原则、统一抽象层次
- **依赖关系优化** - 依赖抽象而非具体实现（DIP）
- **接口设计优化** - 更清晰的契约、更好的解耦

**严禁：**
- 添加新功能
- 删除现有功能
- 改变业务逻辑
- 破坏向后兼容性

---

## 铁律合规检查

**在执行任何优化前，必须完成铁律合规检查：**

```
┌─────────────────────────────────────────────────────────────┐
│                   铁律合规检查流程                           │
├─────────────────────────────────────────────────────────────┤
│  Step 1: 确认优化范围                                       │
│  Step 2: 读取 PRD 文档，确认功能需求（必须保持不变）          │
│  Step 3: 读取架构文档，确认架构约束                          │
│  Step 4: 分析现有代码，理解当前架构                         │
│  Step 5: 制定优化方案（不影响功能）                         │
│  Step 6: 验证优化方案的可行性                               │
└─────────────────────────────────────────────────────────────┘
```

---

## 核心工作流

```
研究现有代码 → [可选]收集参考资料 → 制定优化方案 → 生成task.json → 生成OpenSpec → 实施变更 → 更新状态
```

**步骤说明：**
1. **研究现有代码** - 分析模块边界、设计模式、接口设计、依赖关系
2. **[可选]收集参考资料** - Web搜索/用户提供参考项目/直接使用最佳实践，先询问用户
3. **制定优化方案** - 基于架构原则和参考资料制定方案
4. **生成task.json** - 创建优化任务条目
5. **生成OpenSpec** - 创建变更文档
6. **实施变更** - 执行OpenSpec变更
7. **更新状态** - 更新task.json和progress.txt

## 一、研究现有代码

### 1.1 确定优化范围

**根据用户指定的模块，确定扫描范围：**

| 模块 | 源码路径 |
|------|----------|
| Agent核心 | `src-tauri/src/agent/` + `src/features/agent/` |
| 插件系统 | `src-tauri/src/plugins/` + `src/features/plugin/` |
| 存储层 | `src-tauri/src/storage/` |
| 同步引擎 | `src-tauri/src/sync/` |
| 前端组件 | `src/components/` + `src/features/` |
| 主题系统 | `src/theme/` |

### 1.2 架构分析维度

**从以下维度分析现有架构：**

#### A. 模块边界分析
```bash
# 检查模块间的依赖关系
grep -rn "use\|mod\|import\|require" src-tauri/src/[模块]/ --include="*.rs"
grep -rn "from\|import" src/[模块]/ --include="*.ts" --include="*.tsx"
```

**检查要点：**
- 模块间是否存在循环依赖
- 是否有模块承担了过多职责（违反单一职责）
- 是否有过度耦合的模块
- 依赖方向是否正确（高层依赖低层）

#### B. 设计模式分析
```bash
# 检查是否有builder模式、factory模式等
grep -rn "Builder\|Factory\|Singleton\|Strategy\|Observer" src-tauri/src/[模块]/ --include="*.rs"
grep -rn "class\|interface\|extends\|implements" src/[模块]/ --include="*.ts" --include="*.tsx"
```

**检查要点：**
- 是否存在重复的实例化逻辑（需要工厂模式）
- 是否存在大量条件分支（需要策略模式）
- 是否存在发布-订阅需求（需要观察者模式）
- 配置对象是否复杂（需要builder模式）

#### C. 接口设计分析
```bash
# 检查trait/interface定义
grep -rn "trait\|pub trait" src-tauri/src/[模块]/ --include="*.rs"
grep -rn "interface\|type" src/[模块]/ --include="*.ts"
```

**检查要点：**
- 接口是否过宽（违反接口隔离）
- 是否存在上帝接口
- 接口是否稳定
- 是否有不必要的抽象

#### D. 依赖注入分析
```bash
# 检查依赖注入模式
grep -rn "Arc\|Box\|Rc\|RefCell" src-tauri/src/[模块]/ --include="*.rs"
grep -rn "useContext\|useRef\|createContext" src/[模块]/ --include="*.tsx"
```

**检查要点：**
- 是否依赖具体类型而非抽象
- 是否有过度嵌套的泛型
- 是否有不必要的动态分发

## 三、制定迭代优化方案

### 3.1 方案设计原则

**核心原则：**
1. **功能不变** - 所有优化必须保证现有功能不受影响
2. **渐进式** - 每次优化聚焦一个方面，分步骤进行
3. **可回滚** - 每一步都有明确的回滚方案
4. **可验证** - 每一步都有明确的验证方法

### 3.2 方案结构

## 四、生成 task.json 任务

### 4.1 获取下一个可用ID

```bash
grep -o '"id": [0-9]*' task.json | sort -t: -k2 -n | tail -1
```

### 4.2 生成任务条目

**每个优化阶段对应一个task.json任务：**

```json
{
  "id": [下一个可用ID],
  "epic": "架构优化",
  "story": "优化-[模块名]",
  "title": "[优化阶段名称]",
  "description": "[详细描述]",
  "implementationType": "optimize",
  "phase": "架构升级迭代",
  "priority": "[critical|high|medium|low]",
  "backendRequired": true|false,
  "existingCode": {
    "frontend": ["相关前端文件"],
    "backend": ["相关后端文件"],
    "note": "[现有架构问题总结]"
  },
  "openspec_change": "[待生成的openspec名称]",
  "steps": [
    "[步骤1]",
    "[步骤2]",
    "[步骤3]"
  ],
  "frs_covered": [],
  "nfrs_covered": ["NFR1"],
  "arch_covered": ["ARCH-01"],
  "ux_covered": [],
  "dependencies": [],
  "passes": false,
  "optimization": {
    "preserveFunctions": ["必须保持的功能列表"],
    "verificationMethod": ["验证方法"],
    "rollbackPlan": ["回滚方案"]
  }
}
```

### 4.3 写入 task.json

1. 读取当前 task.json
2. 将新任务追加到 tasks 数组末尾
3. 更新元数据
4. 保存

```
    ├─→ 询问用户意图
    │    ├─→ A: 仅使用最佳实践（默认推荐）
    │    ├─→ B: Web搜索最新资料
    │    ├─→ C: 用户提供参考项目
    │    └─→ D: 跳过此步骤
    │
    ▼
【Step 3】制定优化方案
    │
    ├─→ 设计优化原则
    ├─→ 规划优化阶段
    ├─→ 评估风险
    └─→ 输出优化方案
    │
    ▼
【Step 4】生成 task.json
    │
    ├─→ 获取下一个可用ID
    ├─→ 生成任务条目
    └─→ 写入 task.json
    │
    ▼
【Step 5】生成 OpenSpec
    │
    ├─→ openspec new change
    ├─→ 创建 proposal.md
    ├─→ 创建 design.md
    ├─→ 创建 tasks.md
    └─→ 创建 specs/spec.md
    │
    ▼
【Step 6】实施 OpenSpec 变更
    │
    ├─→ openspec-apply-change
    ├─→ 逐步实施
    ├─→ 验证功能不变
    └─→ 完成实施
    │
    ▼
【Step 7】更新状态
    │
    ├─→ task.json passes = true
    └─→ progress.txt 记录
```
