# 迭代维度详解

本文件为 `product-iterate` skill 的参考资料，详细说明8个迭代评估维度的定义、评估方法和评分标准。

---

## 1. 🎯 需求对齐度（Requirement Alignment）

### 定义

代码实现与PRD文档定义的功能需求的对齐程度。

### 评估方法

1. 读取PRD文档，提取相关模块的FR编号列表
2. 逐个检查每个FR是否有对应代码实现
3. 检查实现是否满足验收标准

### 评分标准

| 分数 | 描述                              |
| ---- | --------------------------------- |
| 5    | PRD需求100%实现，验收标准全部满足 |
| 4    | 90%以上需求实现，少量验收标准微调 |
| 3    | 70-90%需求实现，部分功能缺失      |
| 2    | 50-70%需求实现，核心功能不完整    |
| 1    | 不足50%需求实现，大量核心功能缺失 |

### 关键检查项

- FR编号是否都有对应代码
- 实现方式是否符合PRD描述
- 边界条件和错误处理是否按PRD要求
- 用户旅程是否按PRD定义实现

---

## 2. 🧭 产品方向性（Product Direction）

### 定义

功能实现是否符合产品核心定位和价值主张。

### 评估方法

1. 重新审视产品定位和核心价值
2. 评估每个功能对核心价值的贡献度
3. 识别偏离核心方向的功能或实现

### 评分标准

| 分数 | 描述                                     |
| ---- | ---------------------------------------- |
| 5    | 每个功能都清晰服务于核心价值，无偏离功能 |
| 4    | 核心方向正确，少量功能需调整             |
| 3    | 总体方向正确，但有功能偏离或缺失         |
| 2    | 方向模糊，部分功能与核心价值无关         |
| 1    | 方向不清，大量功能偏离核心               |

### 关键检查项

- 功能是否服务于核心用户场景
- 是否存在"看似有用但偏离核心"的功能
- MVP范围是否合理
- 功能优先级是否反映核心价值

---

## 3. ✨ 用户体验度（User Experience）

### 定义

用户在使用产品过程中的整体体验质量。

### 评估方法

1. 模拟关键用户旅程，检查每个触点的体验
2. 评估交互反馈的及时性和一致性
3. 检查错误处理和边界情况

### 评分标准

| 分数 | 描述                                       |
| ---- | ------------------------------------------ |
| 5    | 核心流程流畅，每步有即时反馈，错误提示友好 |
| 4    | 基本流程顺畅，少量体验摩擦                 |
| 3    | 核心流程可用，但有明显体验问题             |
| 2    | 交互不流畅，缺少反馈，错误处理差           |
| 1    | 基本功能可用性有问题，严重影响使用         |

### 关键检查项

- **即时反馈：** 每个操作都有即时响应（至少视觉反馈）
- **状态可见性：** 用户随时知道"我在哪"、"正在发生什么"
- **错误友好性：** 错误信息用用户语言描述，提供解决建议
- **操作效率：** 常见任务需要多少步骤
- **一致性：** 交互模式是否全局一致
- **空状态处理：** 无数据时是否有引导
- **可访问性：** 键盘操作、屏幕阅读器是否支持

---

## 4. 🔧 技术健康度（Technical Health）

### 定义

代码库的整体技术质量，包括代码质量、架构合理性和技术债务水平。

### 评估方法

1. 静态代码质量分析（TODO/FIXME密度、代码重复度）
2. 架构一致性检查
3. 依赖管理和安全审计

### 评分标准

| 分数 | 描述                               |
| ---- | ---------------------------------- |
| 5    | 代码整洁、架构清晰、无技术债务     |
| 4    | 整体质量高，少量可接受的技术债务   |
| 3    | 质量中等，有需要还债的区域         |
| 2    | 质量堪忧，技术债务开始影响开发效率 |
| 1    | 质量严重低下，需要重构             |

### 关键检查项

- TODO/FIXME密度和分类
- 代码重复度
- 模块职责是否清晰
- 依赖是否合理
- 错误处理是否统一

---

## 5. 🔗 集成完整度（Integration Completeness）

### 定义

前后端、各模块间、与云端的数据流通和功能集成的完整程度。

### 评估方法

1. 检查前后端接口契约是否对齐
2. 检查模块间数据流是否通畅
3. 检查云端同步是否完整

### 评分标准

| 分数 | 描述                           |
| ---- | ------------------------------ |
| 5    | 所有集成点畅通，数据流通完整   |
| 4    | 核心集成完成，少量对接需调整   |
| 3    | 主要集成完成，部分数据流断链   |
| 2    | 集成不完整，功能间无法联动     |
| 1    | 集成严重缺失，模块独立无法协作 |

### 关键检查项

- 前后端API契约对齐
- Tauri命令定义与前端调用一致
- 云端同步逻辑完整性
- 数据格式和类型一致性
- 错误处理链路完整

---

## 6. 🔒 安全合规度（Security Compliance）

### 定义

数据安全、权限控制、隐私保护的完善程度。

### 评估方法

1. 检查认证授权实现
2. 检查数据加密和传输安全
3. 检查输入验证和注入防护

### 评分标准

| 分数 | 描述                           |
| ---- | ------------------------------ |
| 5    | 安全措施完善，通过常见安全审计 |
| 4    | 核心安全到位，少量需加强       |
| 3    | 基本安全措施有，但有明显缺口   |
| 2    | 安全措施不足，存在已知风险     |
| 1    | 安全严重缺失，数据存在泄露风险 |

### 关键检查项

- 认证授权机制
- 敏感数据加密存储
- API通信加密（TLS 1.3）
- 输入验证和XSS/SQL注入防护
- 权限粒度控制

---

## 7. 📊 数据价值度（Data Value）

### 定义

产品对数据采集、分析和决策支持的能力。

### 评估方法

1. 检查关键业务数据的采集点
2. 评估数据分析能力
3. 评估数据对产品决策的支持程度

### 评分标准

| 分数 | 描述                                   |
| ---- | -------------------------------------- |
| 5    | 数据采集完善，分析能力强，数据驱动决策 |
| 4    | 核心数据有采集，基本分析能力           |
| 3    | 部分数据采集，分析能力有限             |
| 2    | 数据采集零散，缺乏分析能力             |
| 1    | 基本无数据采集和分析能力               |

### 关键检查项

- 关键业务数据是否被记录
- 数据分析仪表盘是否可用
- 数据是否能支撑产品决策
- 数据是否用于个性化体验

---

## 8. 🚀 扩展准备度（Extension Readiness）

### 定义

架构是否为下一阶段的需求扩展做好准备。

### 评估方法

1. 评估架构灵活性
2. 评估新功能接入难度
3. 评估性能和容量裕量

### 评分标准

| 分数 | 描述                             |
| ---- | -------------------------------- |
| 5    | 架构灵活，新功能可快速接入       |
| 4    | 架构合理，新功能接入需要少量调整 |
| 3    | 架构尚可，新功能需要一定改造     |
| 2    | 架构僵化，新功能接入困难         |
| 1    | 架构严重耦合，难以扩展           |

### 关键检查项

- 模块边界是否清晰
- 插件系统是否就绪
- 数据模型是否可扩展
- 是否有多租户支持
- 性能是否有增长裕量

---

## 维度权重说明

不同迭代阶段，各维度的权重可以调整：

| 阶段     | 重点关注维度                         | 理由                               |
| -------- | ------------------------------------ | ---------------------------------- |
| MVP阶段  | 需求对齐度 > 产品方向性 > 用户体验度 | 确保方向正确、核心功能实现         |
| 增长阶段 | 用户体验度 > 集成完整度 > 数据价值度 | 优化体验、打通数据、支撑增长       |
| 成熟阶段 | 技术健康度 > 安全合规度 > 扩展准备度 | 还清债务、加强合规、为下一阶段准备 |

评分时应结合当前产品阶段，对不同维度给予不同的重视程度。
